ข้อเลือกตอบ 16 ข้อ กดแล้วเห็นผลและเหตุผลของทุกตัวเลือกทันที ข้อคำนวณทุกข้อทำได้ด้วยมือโดยไม่ใช้เครื่องคิดเลข ส่วนข้อเขียน 3 ข้อให้ลองเขียนก่อนแล้วจึงกดดูเฉลย

ข้อเลือกตอบ

ข้อ 1ใครรัน tool
โค้ด ai_msg = llm_with_tools.invoke(query) ทำงานเสร็จและ ai_msg.tool_calls มี get_invoice ข้อใดถูก
ข้อ 2จำนวนครั้งที่เรียก LLM
single tool execution ใน lab 1 ตั้งแต่รับคำถามถึงได้คำตอบ "Your outstanding invoice balance is $50 USD." เรียก LLM กี่ครั้ง
ข้อ 3parallel_tool_calls
ตั้ง parallel_tool_calls=True ตอน bind_tools แล้วโมเดลคืน tool call 3 ตัว ข้อใดถูก
ข้อ 4latency
tool สี่ตัวใช้เวลา 3, 1, 4, 2 วินาที ทุกตัวอิสระต่อกัน รันพร้อมกันด้วย thread พอเพียง เวลาลดลงจาก sequential กี่เปอร์เซ็นต์
ข้อ 5เลือก topology
ลูกค้าถาม "คืนเงิน order ล่าสุดได้ไหม" ต้องหา order ID ก่อน แล้วดึงรายละเอียด แล้วตัดสินสิทธิ์ topology ใดเหมาะที่สุด
ข้อ 6**data ใน LCEL
ถ้าเขียน get_order_details ให้คืน {"days_since_delivery": 5, "order_status": "Delivered"} โดยไม่มี **data แล้วรัน refund_chain เกิดอะไรขึ้น
ข้อ 7refund eligibility
กฎ order_status == "Delivered" and days_since_delivery <= 14 ข้อมูลใดได้ refund_eligible เป็น True
ข้อ 8router ของ LangGraph
ใน LangGraph ฟังก์ชัน route_issue ที่ส่งให้ add_conditional_edges ควรคืนอะไร
ข้อ 9state ระหว่างทาง
graph customer support รับ initial state มีแค่ user_message และ user_id ขณะ route_issue ทำงาน state มี field ใดแน่นอน
ข้อ 10add_node
นักศึกษานิยามฟังก์ชัน handle_billing แล้วเขียน graph.add_edge("categorize_issue", "handle_billing") โดยไม่เรียก add_node ผลคืออะไร
ข้อ 11tool selection strategy
agent มี tool 300 ตัวที่ไม่ได้แบ่งกลุ่ม ต้องการคุม input token ด้วย top-k ความเสี่ยงหลักของวิธีที่เหมาะคืออะไร
ข้อ 12parameterization error
tool get_invoice(user_id: str) ผู้ใช้ให้ ID U1234 โมเดลสร้าง get_invoice(user_id="U4321") เป็นข้อผิดพลาดแบบใด
ข้อ 13validate argument
ฟังก์ชันใช้ re.fullmatch(r"U\d{4}", user_id) กับการตรวจ isinstance str ค่าใดผ่าน
ข้อ 14memory vs state
ข้อใดอธิบายความต่างของ memory กับ state ได้ถูกตามสไลด์
ข้อ 15เลือกวิธีแก้ปัญหา
งานอธิบายนโยบายคืนสินค้าจากเอกสารบริษัท ไม่ต้องแก้ไขข้อมูลใดในระบบ วิธีใดเหมาะที่สุดตามหลัก "ง่ายที่สุดที่เชื่อถือได้"
ข้อ 16agent pattern
งานตรวจสอบรายงานให้ถูกต้องก่อนส่ง ต้องร่างแล้วตรวจแล้วแก้ซ้ำ pattern ใดเหมาะที่สุด

ข้อเขียน

ข้อ 17ไล่ tool calling ด้วยมือ
agent มี get_invoice, get_refund, get_order ลูกค้าพิมพ์ "Has my refund been processed? My customer ID is U1234." เขียนลำดับขั้นตั้งแต่ข้อความถึงคำตอบ บอกว่าแต่ละขั้นใครทำ และ messages ที่ส่งให้ LLM ครั้งที่สองมีอะไร

ขั้น 1 LLM ที่ bind tool อ่านคำขอ เลือก get_refund และสร้าง args {"user_id": "U1234"} ได้ AIMessage ที่มี tool_calls

ขั้น 2 Python ตรวจชื่อและ argument แล้ว tool_map["get_refund"].invoke(call) ได้ ToolMessage {"user_id": "U1234", "status": "Pending"}

ขั้น 3 ส่ง [HumanMessage(query), ai_msg, tool_msg] ให้ llm ปกติ ได้คำตอบว่า refund ยัง Pending · LLM ถูกเรียก 2 ครั้ง ไม่ได้รันฟังก์ชันเอง

ข้อ 18ออกแบบ graph
เพิ่มประเภท "shipping" ให้ graph customer support: คำขอเรื่องพัสดุไป handle_tracking ระบุว่าต้องแก้ส่วนใดของ classifier, router, การลงทะเบียน node และ edge

classifier: เพิ่ม "shipping" ใน prompt หรือ Literal ของ IssueClassification

node: graph.add_node("handle_tracking", handle_tracking) ที่คืน {"step_result": ...}

router: เพิ่มกรณี issue_type == "shipping" คืน "handle_tracking" และเพิ่ม key ใน path map ของ add_conditional_edges

edge: graph.add_edge("handle_tracking", "summarize_response") เพื่อรวมเส้นทางก่อน END

ข้อ 19parallel หรือ chain
คำขอ "เช็คยอด invoice และสถานะ refund ของฉัน แล้วบอกว่าถ้าได้ refund ยอดคงเหลือจะเป็นเท่าไร" tool get_invoice 2 วินาที get_refund 3 วินาที calculate_balance 1 วินาทีต้องใช้ผลทั้งสองตัว ออกแบบ topology และคำนวณเวลาเทียบกับรันทีละตัว

get_invoice กับ get_refund อิสระต่อกัน รันพร้อมกันได้ ใช้เวลา max(2, 3) = 3 วินาที

calculate_balance ต้องรอผลทั้งสอง จึงต่อท้ายแบบ chain อีก 1 วินาที รวม 4 วินาที

รันทีละตัว 2 + 3 + 1 = 6 วินาที ลดได้ 2/6 ≈ 33% topology ที่ได้คือ parallel ตามด้วยขั้นต่อเนื่อง ซึ่งเขียนเป็น graph ได้
