1. ทำไม Deep Learning ถึง "ทรงพลัง"? สองเหตุผลจากสไลด์

สไลด์เกริ่นด้วยเหตุผล 2 อย่างว่าทำไม Deep Learning เอาชนะ Machine Learning แบบดั้งเดิมได้:

  • Scale for complex tasks — รองรับงานที่ decision boundary ไม่เป็นเส้นตรง หรือมี feature จำนวนมาก (ภาพขนาด 28×28 พิกเซล = \(28\times28 = 784\) features ต่อภาพ)
  • Automate feature engineering — เรียนรู้ feature จากข้อมูลเอง ไม่ต้องให้มนุษย์ออกแบบ feature ทีละตัว

เส้นเวลานี้บอกว่า "backpropagation" (Lesson 3) ไม่ใช่ของใหม่ — Yann LeCun ใช้มันคู่กับ CNN อ่านตัวเลขลายมือสำเร็จตั้งแต่ปี 1989. แต่ Deep Learning ระเบิดความนิยมจริงราวปี 2010 เพราะสองเงื่อนไขที่ขาดมาครบพร้อมกัน: ข้อมูลปริมาณมาก และ พลังประมวลผล (GPU). กราฟด้านขวาของสไลด์แสดงจำนวนพารามิเตอร์ของโมเดลภาษาที่พุ่งขึ้นแบบ exponential หลังปี 2017 (Transformer) เพราะสองเงื่อนไขนี้โตต่อเนื่อง.

ลองเล่นเครื่องมือนี้คู่กับ Lesson 2–3: ปรับจำนวน hidden layer/node แล้วดู decision boundary เปลี่ยนสดๆ — เป็นภาพเดียวกับที่บทถัดไปจะพิสูจน์ด้วยมือว่า "node ยิ่งมาก เส้นแบ่งยิ่งซับซ้อนได้".

2. Linear Regression: จากจุดสองจุดสู่สมการเส้นตรง

Linear regression = ทำนายตัวเลข (เช่นราคา) ด้วยสมการเส้นตรง สไลด์เริ่มด้วยตัวอย่างที่ทำมือได้: มีจุดข้อมูล \((0,0)\) และ \((3,3)\) แล้วถามว่า hypothesis

$$h_\theta(x) = \theta_0 + \theta_1 x$$

\(\theta_0\) คือ "จุดตัดแกน y" (ค่าตอน \(x=0\)), \(\theta_1\) คือ "ความชัน" (x เพิ่ม 1 หน่วย y เพิ่มกี่หน่วย)

คำนวณ: หา \(\theta_0, \theta_1\) จากจุด (0,0) และ (3,3)
  1. หาความชัน \(\theta_1 = \Delta y / \Delta x\)
    $$\theta_1 = \frac{3-0}{3-0} = 1$$
  2. หาจุดตัดแกน \(\theta_0\)

    เส้นผ่านจุด \((0,0)\) แปลว่าตอน \(x=0\) ค่า \(y=0\) ⇒ \(\theta_0 = 0\)

  3. ประกอบสมการ
    $$h_\theta(x) = 0 + 1\cdot x = x$$

สมการทำนายว่า \(y\) เท่ากับ \(x\) เป๊ะ เช่นถ้า \(x=5\) ⇒ ทำนาย \(y=5\) (ตรงกับจุดข้อมูลที่กระจายรอบเส้น \(y=x\) ในสไลด์)

หลายตัวแปร: เมื่อมี feature หลายตัว (ขนาดบ้าน \(x_1\), จำนวนห้องนอน \(x_2\)) แค่บวก term เพิ่ม โครงสร้างเดิมทุกประการ:

$$h_\theta(x) = \theta_0 + \theta_1 x_1 + \theta_2 x_2 + \dots + \theta_n x_n$$
ตัวอย่าง: ทำนายราคาบ้านจากค่า \(\theta\) ที่สมมติ
สมมติ \(\theta_0 = 50\), \(\theta_1 = 0.1\) (ต่อ ตร.ฟุต), \(\theta_2 = 20\) (ต่อห้องนอน) ; บ้าน \(x_1 = 3000\), \(x_2 = 3\)
  1. แทนค่า
    $$h_\theta(x) = 50 + 0.1(3000) + 20(3)$$
  2. คำนวณทีละ term
    $$= 50 + 300 + 60$$
$$h_\theta(x) = 410$$

3. Cost Function & Gradient Descent: ทำไมสูตร \(\theta := \theta - \alpha \,\partial J/\partial\theta\) ถึงเดินเข้าหาค่าต่ำสุด

3.1 Cost function = ตัววัดว่าเส้นของเรา "ผิด" แค่ไหน

สไลด์ (หน้า 29) ใช้ Mean Squared Error (MSE): เอาความต่างระหว่างค่าทำนายกับค่าจริงมายกกำลังสอง (กันค่าบวก/ลบหักล้างกัน) แล้วเฉลี่ย

$$J(\theta) = \frac{1}{m}\sum_{i=1}^{m}\left(h_\theta(x^{(i)}) - y^{(i)}\right)^2$$

ไล่ทุกตัวอย่าง: (ค่าทำนาย − ค่าจริง) ยกกำลังสอง แล้วเฉลี่ย — ยิ่งเส้นห่างจากจุดมาก ค่า J ยิ่งสูง

รูปชามคือกราฟของ \(J(\theta_0,\theta_1)\): แต่ละจุดบนพื้นคือ "ลองค่า \(\theta\) ชุดหนึ่ง" ความสูงคือ cost ของชุดนั้น จุดต่ำสุดของชามคือ \(\theta\) ที่ดีที่สุด. ชามนี้ นูน (convex) มีจุดต่ำสุดจุดเดียว ไม่มีหลุมหลอก — ไม่ว่าเริ่มที่ไหน การไต่ลงจะเจอจุดเดียวกันเสมอ (ต่างจาก neural network ที่ Lesson 3 จะเจอ cost ไม่นูน).

คำนวณ: ค่า cost ของ 3 เส้นที่ต่างกัน
ข้อมูล 3 จุด \((1,1), (2,2), (3,3)\) ; ให้ \(\theta_0=0\) ลองเส้น \(h(x)=\theta_1 x\) กับ \(\theta_1 = 1,\ 0.5,\ 0\)
  1. \(\theta_1 = 1\) (เส้น \(y=x\) ตรงจุดเป๊ะ)
    $$J = \tfrac13\left[(1-1)^2+(2-2)^2+(3-3)^2\right] = 0$$
  2. \(\theta_1 = 0.5\) (ค่าทำนาย 0.5, 1, 1.5)
    $$J = \tfrac13\left[(0.5-1)^2+(1-2)^2+(1.5-3)^2\right] = \tfrac13(0.25+1+2.25) = 1.167$$
  3. \(\theta_1 = 0\) (ทำนาย 0 ทุกจุด)
    $$J = \tfrac13\left[(0-1)^2+(0-2)^2+(0-3)^2\right] = \tfrac13(1+4+9) = 4.667$$

ยิ่งห่างจาก \(\theta_1=1\) ค่า J ยิ่งสูง: \(4.667 \to 1.167 \to 0\) — นี่คือ "ชามหน้าตัด" ของ J เมื่อขยับ \(\theta_1\) อย่างเดียว

3.2 Gradient Descent: เดินลงเขาทีละก้าว

เราไม่ต้องลองทุกค่า \(\theta\) — ใช้อัลกอริทึมที่ "ยืนตรงจุดหนึ่งบนชาม ดูความชัน แล้วก้าวลงเขา" ซ้ำไปเรื่อยๆ:

$$\theta_j := \theta_j - \alpha\,\frac{\partial J}{\partial \theta_j}\qquad(\text{อัปเดตทุก }\theta_j\text{ พร้อมกัน})$$

ค่าใหม่ = ค่าเก่า − (ขนาดก้าว α) × (ความชันของ J ตรงจุดนี้)

ทำไมเครื่องหมายลบทำให้เดินเข้าหาจุดต่ำสุดได้ทั้งสองทาง (คำนวณเป็นกรณีๆ):

ยืนตรงไหนของชามความชัน \(\partial J/\partial\theta\)\(-\alpha \cdot(\text{ความชัน})\)\(\theta\) เปลี่ยนไปทาง
ฝั่งซ้าย (ทางลง)ลบ, เช่น \(-4\)\(-\alpha(-4) = +4\alpha\) บวกเพิ่มขึ้น → ไปทางขวา เข้าหาจุดต่ำสุด
ฝั่งขวา (ทางขึ้น)บวก, เช่น \(+4\)\(-\alpha(+4) = -4\alpha\) ลบลดลง → ไปทางซ้าย เข้าหาจุดต่ำสุด
ที่จุดต่ำสุด\(0\)\(0\)ไม่ขยับ (หยุดเอง)

เครื่องหมายลบจึงทำหน้าที่ "กลับทิศให้เข้าหาจุดต่ำสุดเสมอ" — เหตุผลที่สูตรเป็น \(-\) ไม่ใช่ \(+\).

คำนวณ: gradient descent จริงบนข้อมูล (1,1), (2,2), (3,3) — เริ่มที่ \(\theta_1 = 0\), \(\alpha = 0.05\)
ด้วย J แบบสไลด์ (\(\tfrac1m\sum\)) และ \(\theta_0=0\) ได้ความชัน $$\dfrac{\partial J}{\partial\theta_1} = \dfrac{2}{m}\sum_i (h(x^{(i)})-y^{(i)})\,x^{(i)}$$
  1. รอบที่ 1: หาความชันที่ \(\theta_1=0\) (ค่าทำนายทุกตัว = 0)
    $$\frac{\partial J}{\partial\theta_1} = \tfrac23\left[(0-1)(1)+(0-2)(2)+(0-3)(3)\right] = \tfrac23(-14) = -9.333$$
  2. อัปเดต
    $$\theta_1 := 0 - 0.05(-9.333) = 0.4667$$

    cost ลดจาก 4.667 เหลือ 1.327

  3. รอบที่ 2: ความชันที่ \(\theta_1=0.4667\)
    $$\frac{\partial J}{\partial\theta_1} = \tfrac23\left[(0.4667-1)(1)+(0.9333-2)(2)+(1.4-3)(3)\right] = \tfrac23(-7.467) = -4.978$$ $$\theta_1 := 0.4667 - 0.05(-4.978) = 0.7156$$

    cost เหลือ 0.378

  4. รอบถัดๆ ไป

    \(\theta_1 = 0.8483 \to 0.9191 \to \dots \to 1\) และ cost \(= 0.107 \to 0.031 \to \dots \to 0\)

ก้าวเล็กลงเรื่อยๆ เพราะความชันเล็กลงเมื่อเข้าใกล้ก้นชาม (−9.33 → −4.98 → …) จึงค่อยๆ ลู่เข้า \(\theta_1=1\) (คำตอบที่ถูก) เอง

คำนวณ: learning rate ใหญ่เกินไปเกิดอะไร (\(\alpha = 0.25\), ข้อมูลเดิม)
  1. รอบที่ 1 (ความชันที่ \(\theta_1=0\) = −9.333)
    $$\theta_1 := 0 - 0.25(-9.333) = 2.333$$

    ก้าวไกลจนข้ามจุดต่ำสุด (\(\theta_1=1\)) ไปฝั่งตรงข้าม; cost = 8.30 (สูงขึ้นจาก 4.67!)

  2. รอบที่ 2 (ความชันที่ 2.333 = +12.44)
    $$\theta_1 := 2.333 - 0.25(12.44) = -0.778$$

    ข้ามกลับอีกฝั่ง; cost = 14.75

  3. รอบที่ 3
    $$\theta_1 = 3.370,\quad \text{cost} = 26.2$$

ระยะห่างจากคำตอบ \(|\theta_1 - 1|\) เป็น \(1 \to 1.33 \to 1.78 \to 2.37\) ใหญ่ขึ้นทุกรอบ = diverge (ค่า J สูงขึ้นเรื่อยๆ ไม่ลู่เข้า).

สรุปผลของ \(\alpha\) (สไลด์หน้า 32–33):

  • \(\alpha\) เล็กเกินไป — ก้าวเล็ก ต้องวนหลายรอบกว่าจะถึงก้นชาม (ช้าแต่ปลอดภัย)
  • \(\alpha\) ใหญ่เกินไป — ก้าวข้ามจุดต่ำสุด แกว่งไปมา หรือ diverge (ตัวอย่างข้างบน)
  • วิธีเช็ค: พล็อต \(J\) เทียบกับจำนวนรอบ — ถ้า J ลดลงเรื่อยๆ = α เหมาะสม; ถ้า J ขึ้นๆ ลงๆ หรือพุ่งขึ้น (Cost Overshoot) = α ใหญ่เกินไป ต้องลด

4. Feature Scaling: ทำไมต้อง Normalize ก่อนเทรน

ปัญหา: ถ้า feature หนึ่งมีสเกลใหญ่ (ขนาดบ้าน 1,000–5,000 ตร.ฟุต) แต่อีกตัวเล็ก (ห้องนอน 1–5) contour ของ cost จะยืดเป็นวงรีแคบยาว gradient descent ต้อง zig-zag อ้อมนานกว่าจะถึงจุดต่ำสุด. ถ้าปรับให้ทุก feature อยู่สเกลใกล้กัน contour กลมขึ้นและเดินตรงเข้าหาจุดต่ำสุดได้เร็ว. สูตร min-max normalization ในสไลด์:

$$x_{\text{new}} = \frac{x - \min(x)}{\max(x) - \min(x)}$$

วัดว่าค่านี้อยู่ "กี่ส่วนของช่วง" ตั้งแต่ต่ำสุดถึงสูงสุด — ผลลัพธ์อยู่ใน [0, 1] เสมอ

คำนวณตามสไลด์: normalize 2 feature ที่สเกลต่างกันมาก
  1. size = 3000 (ช่วง [1000, 5000])
    $$x_{\text{new}} = \frac{3000-1000}{5000-1000} = \frac{2000}{4000} = 0.5$$
  2. #bedroom = 3 (ช่วง [1, 5])
    $$x_{\text{new}} = \frac{3-1}{5-1} = \frac{2}{4} = 0.5$$

ค่าตั้งต้นต่างกันมหาศาล (3000 vs 3) แต่ได้ 0.5 เท่ากัน เพราะทั้งคู่อยู่ "กึ่งกลางช่วงของตัวเอง" พอดี — min-max ไม่สนสเกลเดิม สนแค่ตำแหน่งสัมพัทธ์ ทำให้ทุก feature อยู่ [0,1] ก่อนเข้า gradient descent.

อีกวิธีที่สไลด์หน้า 36 กล่าวถึงคือ Mean normalization (z-score) \(x' = \dfrac{x-\mu}{s}\) (ลบค่าเฉลี่ย หารส่วนเบี่ยงเบนมาตรฐาน) — ไม่มีขอบเขต [0,1] แต่เหมาะเมื่อข้อมูลกระจายแบบระฆัง. แนวคิดเดียวกันนี้กลับมาเป็น Batch Normalization ใน Lesson 5.

5. Logistic Regression & Decision Boundary: จากค่า θ สู่เส้นแบ่งที่มองเห็น

Logistic regression ใช้ทำนาย "ใช่/ไม่ใช่" (0 หรือ 1). แทนที่จะปล่อยผลลัพธ์เป็นตัวเลขอะไรก็ได้ มันส่งผลผ่าน sigmoid ให้บีบเข้าช่วง [0, 1] แล้วตีความเป็นความน่าจะเป็น:

$$g(z) = \frac{1}{1+e^{-z}},\qquad h_\theta(x) = g(\theta^\top x) = g(\theta_0 + \theta_1x_1 + \theta_2x_2)$$
คำนวณ: ค่า sigmoid ของ \(z\) ต่างๆ
  1. \(z = 0\)
    $$g(0) = \frac{1}{1+e^{0}} = \frac{1}{2} = 0.5$$

    จุดกึ่งกลาง — ไม่รู้ว่าเป็น 0 หรือ 1

  2. \(z = 2\)
    $$g(2) = \frac{1}{1+e^{-2}} = \frac{1}{1+0.135} = 0.881$$
  3. \(z = -2\)
    $$g(-2) = \frac{1}{1+e^{2}} = \frac{1}{1+7.389} = 0.119$$

\(z\) บวกมาก ⇒ ใกล้ 1, \(z\) ลบมาก ⇒ ใกล้ 0, \(z=0\) ⇒ 0.5 พอดี. จึงตัดสินใจง่ายๆ ว่า ทำนาย \(y=1\) เมื่อ \(z \ge 0\) (เพราะ \(g(z)\ge0.5\)) เส้น \(z=0\) คือ decision boundary.

ตัวอย่างซ้ายของสไลด์ (เส้นตรง): \(\theta_0=0,\ \theta_1=-1,\ \theta_2=1\), ทดสอบจุด \(x_1=100,\ x_2=90\)
  1. หา \(z\)
    $$z = 0 + (-1)(100) + (1)(90) = -100 + 90 = -10$$
  2. ตัดสินใจ

    \(-10 < 0\) ⇒ \(g(-10) \approx 0\) ⇒ ทำนาย \(y=0\) ("Available")

  3. หาเส้นแบ่ง
    $$-x_1 + x_2 = 0 \;\Rightarrow\; x_2 = x_1$$

    จุดที่ \(x_2 > x_1\) ได้ \(z>0\) ⇒ Sold (ฝั่งบนของเส้น); จุดที่ \(x_2 < x_1\) ⇒ Available (ฝั่งล่าง) เช่นจุดทดสอบ (100, 90) อยู่ใต้เส้น

ตัวอย่างขวาของสไลด์ (วงกลม): \(\theta_0=-4,\ \theta_1=1,\ \theta_2=1\) บน feature ยกกำลังสอง \(x_1^2, x_2^2\)
  1. เขียน \(z\)
    $$z = -4 + x_1^2 + x_2^2$$
  2. ทดสอบจุด \((0,0)\)
    $$z = -4 + 0 + 0 = -4 < 0 \;\Rightarrow\; y=0\ (\text{Available})$$
  3. หาเส้นแบ่ง \(z=0\)
    $$x_1^2 + x_2^2 = 4 = 2^2$$

    คือวงกลมรัศมี 2 รอบจุดกำเนิด — จุดในวง (\(x_1^2+x_2^2<4\)) ได้ \(z<0\) ⇒ Available; จุดนอกวง ⇒ Sold

แค่เปลี่ยน feature จาก \(x\) เป็น \(x^2\) เส้นแบ่งก็เปลี่ยนจากเส้นตรงเป็นวงกลม โดยสมการยังเป็น "เชิงเส้นใน \(\theta\)" เหมือนเดิม — แนวคิดเดียวกับที่ hidden layer ใน neural network สร้าง feature ใหม่ให้เอง (Lesson 2).

คำถาม 3Decision Boundary
ให้ θ₀=0, θ₁=−1, θ₂=1 และทำนาย y=1 ("Sold") เมื่อ θ₀+θ₁x₁+θ₂x₂ > 0 ที่จุด x₁=100, x₂=90 โมเดลทำนายว่าอะไร?
คำถาม 4Decision Boundary
Non-linear decision boundary จาก θ₀=−4, θ₁=1, θ₂=1 บน x₁²,x₂² (ทำนาย y=1 เมื่อ θ₀+θ₁x₁²+θ₂x₂² ≥ 0) มีรูปทรงและขนาดอย่างไร?

6. Cost Function ของ Classification: ทำไมใช้ Log Loss แทน MSE

ถ้าเอา MSE ไปใช้กับ sigmoid จะได้ cost ที่ไม่นูน (มีหลุมหลอกหลายจุด) gradient descent จึงอาจติดหลุมได้. สไลด์ (หน้า 44) จึงใช้ Cross-Entropy / Log Loss ต่อ 1 ตัวอย่าง:

$$\text{Cost}\big(h_\theta(x), y\big) = -y\log\big(h_\theta(x)\big) - (1-y)\log\big(1-h_\theta(x)\big)$$

มีเพียงเทอมเดียวที่ "ทำงาน" เสมอ: ถ้า \(y=1\) เหลือ \(-\log h\); ถ้า \(y=0\) เหลือ \(-\log(1-h)\)

คำนวณ: ค่า cost เมื่อ \(y=1\) และโมเดลมั่นใจต่างกัน
  1. \(h = 0.9\) (ทำนายถูก มั่นใจสูง)
    $$-\ln(0.9) = 0.105$$
  2. \(h = 0.5\) (ไม่แน่ใจ)
    $$-\ln(0.5) = 0.693$$
  3. \(h = 0.1\) (ทำนายผิด มั่นใจสูง)
    $$-\ln(0.1) = 2.303$$
  4. \(h = 0.01\) (ผิดอย่างมั่นใจมาก)
    $$-\ln(0.01) = 4.605$$

ยิ่งทำนายผิดมั่นใจ cost ยิ่งพุ่ง (\(h \to 0\) ⇒ cost \(\to \infty\)) และทำนายถูกมั่นใจ (\(h\to1\)) ⇒ cost \(\to 0\) — ตรงกับกราฟสไลด์ "ลงโทษหนักเมื่อผิดอย่างมั่นใจ". ตัวเลข 0.693 = ln 2 จะกลับมาเป็นค่า cost เริ่มต้นของโมเดลที่ยังไม่เรียนรู้ใน Lesson 3–4.

เมื่อรวมทุกตัวอย่าง (cross-entropy loss) แล้วหา gradient จะได้สูตรอัปเดตหน้าตาเดียวกับ linear regression (สไลด์หน้า 45):

$$\theta_j := \theta_j - \alpha\,\frac{1}{m}\sum_{i=1}^{m}\left(h_\theta(x^{(i)}) - y^{(i)}\right)x_j^{(i)}$$

เหตุผลที่ลดรูปได้ขนาดนี้: อนุพันธ์ของ log loss ไปตัดกับอนุพันธ์ของ sigmoid \(g'(z)=g(z)(1-g(z))\) พอดี (พิสูจน์เต็มใน Lesson 3) ทำให้เหลือแค่ "ค่าทำนาย − ค่าจริง" คูณ feature.

7. Metrics: Confusion Matrix, ROC/AUC

เมื่อทำนายแบบ 2 คลาส ผลแต่ละตัวอย่างตกใน 4 ช่อง: TP (ทำนายบวก จริงบวก), TN (ทำนายลบ จริงลบ), FP (ทำนายบวก แต่จริงลบ), FN (ทำนายลบ แต่จริงบวก). สูตรจากสไลด์:

$$\text{accuracy}=\frac{TP+TN}{TP+TN+FP+FN},\quad \text{precision}=\frac{TP}{TP+FP},\quad \text{recall}=\frac{TP}{TP+FN},\quad F_1=\frac{2\cdot\text{precision}\cdot\text{recall}}{\text{precision}+\text{recall}}$$
คำนวณ: ทำนาย 100 กรณี ได้ TP = 40, TN = 45, FP = 5, FN = 10
  1. accuracy — ถูกกี่ % จากทั้งหมด
    $$\frac{40+45}{40+45+5+10} = \frac{85}{100} = 0.85$$
  2. precision — ที่ทำนายว่าบวก 45 ครั้ง ถูกจริงกี่ครั้ง
    $$\frac{40}{40+5} = \frac{40}{45} = 0.889$$
  3. recall — ของจริงที่เป็นบวก 50 ตัว จับได้กี่ตัว
    $$\frac{40}{40+10} = \frac{40}{50} = 0.80$$
  4. \(F_1\) — ค่าเฉลี่ยแบบ "harmonic" ของสองตัวข้างบน
    $$F_1 = \frac{2(0.889)(0.80)}{0.889+0.80} = 0.842$$

trade-off: อยากได้ recall สูง (จับบวกให้ครบ) มักต้องยอมทำนายบวกมั่วมากขึ้น ⇒ precision ต่ำลง และกลับกัน.

ROC ไม่ใช่ตัวเลขค่าเดียว แต่เป็นกราฟที่ไล่ threshold ตัดสินใจ (ปกติ 0.5) แล้ววาด \(\text{TPR}=\frac{TP}{TP+FN}\) กับ \(\text{FPR}=\frac{FP}{FP+TN}\) ที่ทุก threshold:

คำนวณ: 1 จุดบน ROC ต่อ 1 threshold (ตัวอย่างข้อมูล 6 ตัว)
คะแนนที่โมเดลให้ (คำตอบจริง): 0.9 (1), 0.8 (1), 0.6 (0), 0.55 (1), 0.4 (0), 0.2 (0) — มีบวกจริง 3 ตัว ลบจริง 3 ตัว
  1. threshold = 0.5 (ทำนายบวกเมื่อคะแนน ≥ 0.5 ⇒ 0.9, 0.8, 0.6, 0.55)

    TP = 3 (0.9, 0.8, 0.55), FP = 1 (0.6), FN = 0, TN = 2

    $$\text{TPR} = \tfrac{3}{3} = 1.00,\qquad \text{FPR} = \tfrac{1}{3} = 0.33$$
  2. threshold = 0.7 (ทำนายบวก ⇒ 0.9, 0.8)

    TP = 2, FP = 0, FN = 1, TN = 3

    $$\text{TPR} = \tfrac{2}{3} = 0.67,\qquad \text{FPR} = \tfrac{0}{3} = 0$$

สองจุด (FPR, TPR) = (0.33, 1.00) และ (0, 0.67) — ไล่ threshold ทั้งหมดแล้วต่อจุดเป็นเส้นโค้ง ยิ่งโค้งขึ้นชิดมุมซ้ายบน (พื้นที่ใต้กราฟ AUC → 1) โมเดลยิ่งแยกสองคลาสได้ดี; เส้นทะแยง 45° = การเดาสุ่ม (AUC = 0.5).

8. Multiclass: One-vs-Rest และ Softmax

One-vs-Rest: ถ้ามี \(k\) คลาส เทรน logistic regression \(k\) ตัว แต่ละตัวตอบ "เป็นคลาสนี้ หรือไม่" (ในรูป 3 คลาส ⇒ เทรน 3 โมเดล เอาคลาสหนึ่งเทียบกับที่เหลือรวมกัน) แล้วเลือกคลาสที่ \(h^{(k)}(x)\) สูงสุด. ข้อเสียคือต้องเทรน \(k\) โมเดลแยกกัน.

Softmax (สไลด์หน้า 50) แก้ด้วยโมเดลเดียว: แปลงคะแนนดิบ \(z_i\) (logit) ของทุกคลาสเป็นความน่าจะเป็นที่รวมกันได้ 1:

$$a_i = \frac{e^{z_i}}{\sum_{n} e^{z_n}}$$
คำนวณ: softmax ของ logit \(z = [2,\ 1,\ 0]\)
  1. ยกกำลัง \(e\) ทีละตัว
    $$e^2 = 7.389,\quad e^1 = 2.718,\quad e^0 = 1$$
  2. รวม
    $$7.389 + 2.718 + 1 = 11.107$$
  3. หารแต่ละตัวด้วยผลรวม
    $$a = \left[\tfrac{7.389}{11.107},\ \tfrac{2.718}{11.107},\ \tfrac{1}{11.107}\right] = [0.665,\ 0.245,\ 0.090]$$
  4. ตรวจสอบ
    $$0.665 + 0.245 + 0.090 = 1.000$$

คลาสแรกชนะที่ 66.5%. เหตุผลที่ใช้ \(e^{z}\) แทนหารสัดส่วนดิบ (\(2/3 = 0.667\) ก็ดูใกล้กันแต่ใช้ไม่ได้ในทั่วไป): (1) \(z\) อาจติดลบ (สัดส่วนดิบจะเพี้ยน) แต่ \(e^z\) เป็นบวกเสมอ (2) \(e^z\) ขยายค่าที่มากที่สุดให้เด่นขึ้น ทำให้โมเดล "ไม่เป็นกลางเกินไป".

คำนวณ: loss ของ softmax (สไลด์หน้า 50) เมื่อคลาสที่ถูกคือคลาสแรก
  1. \(y=[1,0,0]\) (one-hot) เหลือเทอมเดียวที่ไม่เป็น 0
    $$J = -\sum_k y_k \ln a_k = -\ln(0.665) = 0.408$$
  2. ถ้าคลาสที่ถูกคือคลาสที่สาม (\(a_3 = 0.090\))
    $$J = -\ln(0.090) = 2.408$$

โมเดลให้ความน่าจะเป็นกับคลาสที่ถูกน้อย ⇒ loss สูง (2.408 เทียบ 0.408). คือ cross-entropy เดียวกับข้อ 6 ที่ขยายเป็นหลายคลาส.

คำถาม 5Softmax
เหตุผลหลักที่ softmax ใช้ e^z (exponential) แทนการเอาค่า z มาหารด้วยผลรวมตรงๆ (เช่น zᵢ/Σzₙ) คืออะไร?

9. Model Evaluation: Train/Validation/Test และ k-fold Cross Validation

ทำไมต้องแบ่งข้อมูล: ถ้าวัดผลบนข้อมูลที่ใช้เทรน โมเดลที่ "ท่องจำ" ก็ได้คะแนนสูง ทั้งที่ทำนายข้อมูลใหม่ไม่ได้. จึงแบ่งเป็น train (ให้เรียนรู้), validation (ใช้เลือก hyperparameter) และ test (สอบจริงครั้งเดียวตอนท้าย). ตัวอย่าง 3-fold ในสไลด์:

  1. แบ่ง 80–20

    ข้อมูลทั้งหมดแบ่งเป็น train 80% / test 20% (test เก็บไว้ ยังไม่แตะ)

  2. แบ่ง train เป็น 3 fold เท่าๆ กัน

    เช่น 300 แถว ⇒ fold ละ 100 แถว

  3. หมุนเวียน 3 รอบ

    รอบ 1: เก็บ Fold 1 ไว้ตรวจ เทรนด้วย Fold 2+3 · รอบ 2: เก็บ Fold 2 เทรนด้วย 1+3 · รอบ 3: เก็บ Fold 3 เทรนด้วย 1+2

  4. เฉลี่ยผล

    ตัวอย่างสมมติ error 3 รอบ = 0.20, 0.24, 0.22 ⇒ คะแนนของ hyperparameter ชุดนี้ = \(\frac{0.20+0.24+0.22}{3} = 0.22\)

  5. เลือกชุดที่คะแนนเฉลี่ยดีที่สุด แล้วค่อยแตะ test 20% ครั้งเดียว

ข้อสำคัญ: test 20% ไม่ถูกแตะจนกว่าเลือก hyperparameter เสร็จ ไม่งั้นตัวเลข test จะ "ถูกมองเห็น" ระหว่างเลือกโมเดลและกลายเป็นตัวเลขที่ดูดีเกินจริง (เหตุผลเดียวกับ Lesson 6 §10: validation 0.8936 สูงกว่า test 0.8845).

10. Bias vs Variance: วินิจฉัยจากกราฟ \(J_{\text{train}}\) กับ \(J_{cv}\)

นิยามง่ายๆ: \(J_{\text{train}}\) = cost บนข้อมูลที่โมเดลเคยเห็น, \(J_{cv}\) = cost บนข้อมูล validation ที่ไม่เคยเห็น. สองค่านี้บอกโรคของโมเดลได้:

\(J_{\text{train}}\)\(J_{cv}\)วินิจฉัยตัวอย่างตัวเลขวิธีแก้
สูงสูง (ใกล้ \(J_{\text{train}}\))High bias (underfit) โมเดลง่ายไป0.30 / 0.32เพิ่มความจุ: degree/feature/layer
ต่ำมากสูงกว่ามากHigh variance (overfit) จำ noise0.02 / 0.25เพิ่มข้อมูล, regularization, ลดความจุ
ต่ำต่ำ (ใกล้กัน)พอดี0.05 / 0.07—

ในกราฟ: ที่ degree \(d\) น้อย (เช่น \(h=\theta_0+\theta_1x\) เส้นตรง) ทั้งสองเส้นสูง = high bias; ที่ \(d\) มาก (เช่น \(h=\theta_0+\theta_1x+\dots+\theta_4x^4\) เส้นหยักผ่านทุกจุด) \(J_{\text{train}}\) ต่ำมากแต่ \(J_{cv}\) สูง = high variance; จุดที่ดีที่สุดคือ \(d=2\) ที่สองเส้นต่ำพร้อมกัน. bias กับ variance สวนทางกัน (อุดมคติคือต่ำทั้งคู่).

คำถาม 6Bias vs Variance
ถ้าพบว่า Jtrain(θ) ต่ำมาก แต่ Jcv(θ) สูงมาก ควรวินิจฉัยปัญหาของโมเดลว่าอะไร และวิธีแก้ที่เหมาะสมที่สุดคือข้อใด?

11. Regularization: บีบ θ ให้เล็กโดยไม่ทิ้ง feature

แทนที่จะตัด feature ทิ้ง (เสียข้อมูล) L2 regularization เพิ่ม "ค่าปรับ" ตามขนาดของ \(\theta\) เข้าไปใน cost (ตามสไลด์: บวก \(\frac{\lambda}{m}\sum_{j=1}^{n}\theta_j^2\); ไม่ปรับ \(\theta_0\)):

$$J(\theta) = \frac{1}{m}\sum_{i=1}^{m}\left(h_\theta(x^{(i)})-y^{(i)}\right)^2 + \frac{\lambda}{m}\sum_{j=1}^{n}\theta_j^2$$

cost เดิม + ค่าปรับที่ยิ่ง \(\theta\) ใหญ่ยิ่งแพง — โมเดลจึง "ประหยัด" ไม่ให้ \(\theta\) พองเพื่อไล่ตาม noise

คำนวณ: ค่าปรับ และผลต่อการอัปเดต
สมมติ \(\theta_1=3,\ \theta_2=-2,\ \theta_3=0.5\), \(\lambda=1\), \(m=10\)
  1. รวมกำลังสองของ θ (ไม่รวม θ₀)
    $$\sum\theta_j^2 = 9 + 4 + 0.25 = 13.25$$
  2. ค่าปรับ
    $$\frac{\lambda}{m}\sum\theta_j^2 = \frac{1}{10}(13.25) = 1.325$$

    ยิ่งบวกเข้า cost ⇒ ต้องลด \(\theta\) เพื่อลดค่าปรับ (ตัวที่ใหญ่ที่สุด \(\theta_1=3\) ถูกกดแรงที่สุด เพราะโทษโตเป็นกำลังสอง)

  3. ผลต่อ gradient descent (เทอมค่าปรับหาอนุพันธ์ได้ \(\frac{2\lambda}{m}\theta_j\))
    $$\theta_j := \theta_j\left(1 - \frac{2\alpha\lambda}{m}\right) - \alpha\,\frac{\partial J_{\text{data}}}{\partial\theta_j}$$

    ถ้า \(\alpha = 0.1\): ตัวคูณ \(1 - \frac{2(0.1)(1)}{10} = 0.98\) — ทุกรอบ \(\theta\) ถูกลดลง 2% ก่อน แล้วค่อยเดินตาม gradient (จึงเรียกว่า weight decay)

ยิ่ง \(\lambda\) มากยิ่งบีบ \(\theta\) เล็กลง. ถ้า \(\lambda\) ใหญ่เกินจน \(\theta_j\to 0\) ทุกตัว ⇒ \(h_\theta(x)\approx\theta_0\) เป็นเส้นแบนราบ (ตามที่ท้ายสไลด์เขียน "\(h_\theta(x)\approx\theta_0\)") กลายเป็น high bias — ดังนั้น \(\lambda\) เป็น hyperparameter ที่ต้องหาจุดสมดุลด้วย cross-validation เหมือนการเลือก degree. (Lesson 4 §6 และ Lesson 6 ใช้แนวคิดเดียวกัน; Keras เรียกว่า l2(λ) ที่ Lesson 5.)

โมเดลที่ยืดหยุ่นมาก (เช่น polynomial degree สูง) ไล่ตาม noise ได้ด้วยการใช้ \(\theta\) ค่าใหญ่ๆ ที่หักล้างกันเพื่อสร้างเส้นหยัก. ค่าปรับทำให้ "การใช้ \(\theta\) ใหญ่" มีราคา จึงเลือกเส้นที่เรียบกว่าเมื่อข้อมูลไม่ได้บังคับจริงๆ.
เปลี่ยนแล้วเกิดอะไร
\(\lambda=0\) ⇒ ไม่มีค่าปรับ (เสี่ยง overfit); \(\lambda\) ปานกลาง ⇒ เส้นเรียบขึ้น \(J_{cv}\) ลดลง; \(\lambda\) มหาศาล ⇒ \(\theta\to0\) เส้นแบน \(J_{\text{train}}\) และ \(J_{cv}\) สูงทั้งคู่ (underfit). ยิ่งข้อมูลมากขึ้น ผล overfit ยิ่งลดเอง (สไลด์หน้า 58: เพิ่มข้อมูลช่วย high variance).

12. Unsupervised Learning: K-means Clustering

K-means ต่างจากหัวข้อก่อนหน้าตรงที่ ไม่มี label \(y\) — อัลกอริทึมจัดกลุ่มจากโครงสร้างของข้อมูลเอง โดยเริ่มจากสุ่ม centroid \(K\) จุด แล้ววนสองขั้นตอนสลับกันจนไม่เปลี่ยน:

  1. Assign: ให้แต่ละจุดข้อมูลสังกัด centroid ที่ใกล้ที่สุด
  2. Update: ย้าย centroid แต่ละตัวไปที่ค่าเฉลี่ยของจุดที่สังกัดมัน: \(\mu_k = \frac{1}{|C_k|}\sum_{x\in C_k} x\)
คำนวณ: K-means 1 มิติ, \(K=2\), ข้อมูล 1, 2, 3, 10, 11, 12 — เริ่ม centroid ที่ \(\mu_1=1,\ \mu_2=2\)
  1. รอบที่ 1 — Assign

    จุด 1 → \(\mu_1\) (ระยะ 0 เทียบ 1) ; จุด 2 → \(\mu_2\) (0 เทียบ 1) ; จุด 3 → \(\mu_2\) (1 เทียบ 2) ; จุด 10, 11, 12 → \(\mu_2\)

  2. รอบที่ 1 — Update
    $$\mu_1 = 1,\qquad \mu_2 = \frac{2+3+10+11+12}{5} = 7.6$$
  3. รอบที่ 2 — Assign ใหม่ด้วย \(\mu=(1,\ 7.6)\)

    จุด 1, 2, 3 → \(\mu_1\) (เช่นจุด 3: ระยะ 2 เทียบ 4.6) ; จุด 10, 11, 12 → \(\mu_2\)

  4. รอบที่ 2 — Update
    $$\mu_1 = \frac{1+2+3}{3} = 2,\qquad \mu_2 = \frac{10+11+12}{3} = 11$$
  5. รอบที่ 3 — Assign อีกครั้ง

    การสังกัดเหมือนรอบที่ 2 ทุกจุด ⇒ ไม่เปลี่ยนแล้ว (converge)

ได้ 2 กลุ่ม {1,2,3} และ {10,11,12} ที่ centroid = 2 และ 11 แม้เริ่มจากจุดเริ่มต้นที่ไม่ดี. ไม่มีขั้นตอนไหนใช้ gradient descent หรือ label เลย.

คำถาม 7K-means
ในขั้นตอน "Update" ของ K-means algorithm หลังจาก assign จุดข้อมูลเข้ากลุ่มแล้ว ตำแหน่งใหม่ของ centroid μₖ แต่ละตัวคำนวณจากอะไร?
