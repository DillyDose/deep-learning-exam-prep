1. ทำไมต้อง Neural Network: ปัญหาของ Polynomial Feature

วิธีเดิมในการทำ decision boundary ไม่เป็นเส้นตรง (จาก Lesson 1) คือเพิ่ม polynomial feature เช่น x₁², x₁x₂ เข้าไปใน logistic regression.

ปัญหาคือพอ feature ตั้งต้นมีจำนวนมาก จำนวน polynomial term ที่ต้องสร้างจะระเบิดเร็วมาก.

ไล่ตัวเลขตามสไลด์: ถ้ามี input แค่ x₁,x₂ การเพิ่ม polynomial degree 2 ให้ครบ (x₁²,x₂²,x₁x₂) ยังจัดการได้ไม่ยาก แต่พอมี x₁,x₂,…,x₁₀₀ (100 features) แค่ทำ polynomial degree 2 ให้ครบทุกคู่ (x₁xⱼ สำหรับทุก i,j) จำนวน term รวมพุ่งไปถึง 5,150 features — และนี่คือ degree 2 เท่านั้น.

ถ้าเป็นภาพสี RGB ขนาด 28×28 พิกเซล (จะคำนวณด้านล่าง) จำนวน input feature ตั้งต้นก็ปาไป 2,352 แล้ว การทำ polynomial expansion บนขนาดนี้จึงไม่มีทางทำได้จริงในทางปฏิบัติ — นี่คือ "ปัญหา" ที่ทำให้ต้องมีวิธีใหม่ในการสร้าง non-linear decision boundary โดยไม่ต้องเพิ่ม feature มือเอง.

สไลด์หน้าถัดมาให้คำนวณจำนวน feature ของภาพจริง:

  • ภาพ grayscale ขนาด 28×28 พิกเซล มีจำนวน feature = 28×28 = 784 (แต่ละพิกเซลคือ 1 feature ค่า [0-255])
  • ภาพสี RGB ที่มี 3 channel (แดง เขียว น้ำเงิน) ต่อพิกเซล จะได้ 784×3 = 2,352 features

ยิ่งตอกย้ำว่าการเพิ่ม polynomial term มือด้วยจำนวน feature ระดับพันแบบนี้เป็นไปไม่ได้เลย.

2. ประวัติย่อของ ANN: จาก McCulloch-Pitts สู่ปัญหา XOR

โมเดลนิวรอนแรกสุด (1943) รับ input แบบ binary (on/off) แล้ว activate output เมื่อจำนวน input ที่ active เกินเกณฑ์ที่กำหนด — เรียบง่ายแต่พิสูจน์แล้วว่าคำนวณ logic proposition (AND, OR, NOT) ได้ครบ.

Perceptron (1957) พัฒนาต่อให้รับ input เป็นตัวเลขจริง (ไม่จำเป็นต้อง binary) คูณด้วย weight บวกกัน แล้วผ่าน step function.

แต่ Minsky (1969) พิสูจน์ว่า TLU เดี่ยวตัวเดียวแก้ปัญหา XOR ไม่ได้ เพราะ XOR ไม่ใช่ linearly separable (ไม่มีเส้นตรงเส้นเดียวที่แบ่ง (0,0)/(1,1)→0 ออกจาก (0,1)/(1,0)→1 ได้).

นี่คือคำตอบที่ทำให้ต้องมี "หลาย layer": ใช้ TLU 2 ตัวใน hidden layer แทน 1 ตัว:

  • ตัวแรกคำนวณ step(x₁+x₂−1.5) (ให้ 1 เฉพาะ x₁=x₂=1 พอดี คือทำหน้าที่เหมือน AND)
  • ตัวที่สองคำนวณ step(x₁+x₂−0.5) (ให้ 1 เมื่อมีอย่างน้อยหนึ่งตัวเป็น 1 คือทำหน้าที่เหมือน OR)

แล้ว output รวมสองค่านี้เป็น step(OR − AND − 0.5) ลองแทนค่าจริง:

  • x₁=1,x₂=1 → AND=step(2−1.5)=1, OR=step(2−0.5)=1, output=step(1−1−0.5)=step(−0.5)=0 (ถูก เพราะ XOR(1,1)=0)
  • x₁=1,x₂=0 → AND=step(1−1.5)=0, OR=step(1−0.5)=1, output=step(1−0−0.5)=step(0.5)=1 (ถูก เพราะ XOR(1,0)=1)

นี่คือหลักฐานที่จับต้องได้ว่า "ต่อ TLU สองตัวเป็นสอง layer" แก้ปัญหาที่ TLU เดี่ยวแก้ไม่ได้.

กลไกที่ต้องอธิบายได้
ทำไมต้องมี
เกณฑ์ที่แท้จริงไม่ใช่ "XOR ยากเป็นพิเศษ" แต่คือ linear separability: TLU เดี่ยวตัดพื้นที่ด้วยไฮเปอร์เพลนเดียวเท่านั้น ถ้าจุดสอง class จัดเรียงแบบสลับมุม (checkerboard) อย่าง XOR ไม่มีเส้นตรงเส้นเดียวแบ่งได้ ไม่ว่าจะปรับ θ ยังไงก็ตาม — ต้องมี hidden layer มาตัดพื้นที่เป็นหลายส่วนก่อนค่อยรวมผล
เปลี่ยนแล้วเกิดอะไร
ลองเปลี่ยนโจทย์เป็น "majority of 3" (output=1 ถ้า input เป็น 1 อย่างน้อย 2 จาก 3 ตัว) — ฟังก์ชันนี้ linearly separable เพราะเรียงจุดตาม x₁+x₂+x₃ แล้วตัดที่ threshold 1.5 ได้เลย (θ=[−1.5,1,1,1]) ต่าง XOR ตรงที่ output ไม่สลับ parity แบบ checkerboard TLU เดี่ยวจึงพอ ไม่ต้องมี hidden layer
เชื่อมกับ
เกณฑ์เรขาคณิตเดียวกับ decision boundary ใน Lesson 1 (เส้นตรง vs วงกลม) — "linearly separable หรือไม่" คือคำถามเดียวที่ใช้ตัดสินว่าต้องเพิ่ม layer/feature หรือไม่ตลอดทั้งวิชา
คำถาม 2XOR Problem

3. สัญกรณ์ของ Neural Network: θ, Layer, Node

สัญกรณ์นี้ใช้ไปตลอดวิชา ต้องแม่น: a_j^[l] คือ activation ของ node ที่ j ใน layer ที่ l (ตัวเลขใน [ ] คือ layer ไม่ใช่ยกกำลัง) ส่วน θ_ij^[l] คือ weight ของเส้นเชื่อมที่วิ่งเข้าไปที่ node i ในเลเยอร์ l โดยมาจาก node j ในเลเยอร์ l−1.

สังเกตว่าลำดับ subscript คือ "ปลายทาง,ต้นทาง" (i=ปลายทาง, j=ต้นทาง) ไม่ใช่ "ต้นทาง,ปลายทาง" ซึ่งเป็นจุดที่มักสับสน.

สูตรหลักที่ใช้ตลอด: z_j^[l] = Σᵢ θ_ji^[l] · xᵢ (ผลรวมถ่วงน้ำหนักก่อนเข้า activation function) แล้ว a_j^[l] = g(z_j^[l]) (ผลลัพธ์หลังผ่าน activation function g).

bias unit x₀ ถูกกำหนดค่าคงที่ +1 เสมอ (ไม่ใช่ input จริงจากข้อมูล) ทำหน้าที่เดียวกับ θ₀ ใน logistic regression ของ Lesson 1 คือขยับเส้น/ระนาบให้ไม่ต้องผ่านจุดกำเนิดเสมอไป.

กลไกที่ต้องอธิบายได้
ทำไมต้องมี
ลำดับ subscript (i=ปลายทาง,j=ต้นทาง) ไม่ใช่แค่ธรรมเนียม แต่ทำให้สูตร z=θ·a ตรงกับกฎ matrix-vector multiplication พอดี: แถวของ θ คือ index ปลายทาง i (จำนวนแถว=จำนวน node ปลายทาง) คอลัมน์คือ index ต้นทาง j (จำนวนคอลัมน์=จำนวน node ต้นทาง+1 สำหรับ bias) ตรงกับจำนวนสมาชิกใน a พอดี ถ้าสลับ i,j มิติจะคูณกันไม่ได้เลย
เปลี่ยนแล้วเกิดอะไร
ถ้า layer ก่อนหน้ามี 4 node (ไม่รวม bias) และ layer ปัจจุบันมี 2 node, θ ของ layer นี้ต้องมี dimension 2×(4+1)=2×5 — ถ้าจำ i,j สลับกันจะเผลอเขียนเป็น 4×3 ซึ่งคูณกับเวกเตอร์ a (5 สมาชิก รวม bias) ไม่ได้เลย numpy จะ error ทันที (shape mismatch)
เชื่อมกับ
กฎการอ่าน matrix index (แถวก่อนคอลัมน์หลัง) ในหัวข้อ 5 ของบทนี้ และ "Dimension of Parameters" ที่ Lesson 3 นำสูตรนี้ไปทำให้เป็นทางการอีกที
คำถาม 3Notation
ในสัญกรณ์ θ_ij^[l] ตัวเลข i และ j แต่ละตัวหมายถึงอะไร?

4. Logic Gates เป็น Neuron เดี่ยว: AND, OR, NOT

ตัวอย่างที่ทำให้เห็นภาพชัดว่า 1 node ทำอะไรได้: ใช้ node เดียว (sigmoid) แทน logic gate ได้ทั้ง AND, OR, NOT โดยเลือกค่า θ ให้เหมาะสม.

ตั้ง θ₀=−30, θ₁=20, θ₂=20 คำนวณครบ 4 กรณี:

  • x₁=0,x₂=0 → g(−30)≈0
  • x₁=0,x₂=1 → g(−30+20)=g(−10)≈0
  • x₁=1,x₂=0 → g(−10)≈0
  • x₁=1,x₂=1 → g(−30+20+20)=g(10)≈1

เพราะ sigmoid(z) เข้าใกล้ 0 เมื่อ z เป็นลบมากๆ และเข้าใกล้ 1 เมื่อ z เป็นบวกมากๆ ผลลัพธ์ตรงกับ AND truth table ครบทั้ง 4 แถวพอดี (ให้ 1 เฉพาะกรณีที่ทั้งสอง input เป็น 1).

สไลด์นี้เว้นคำตอบไว้ให้กรอกในคาบเรียน — คำนวณให้ครบด้วย θ₀=−10, θ₁=20, θ₂=20:

  • x₁=0,x₂=0 → g(−10)≈0
  • x₁=0,x₂=1 → g(−10+20)=g(10)≈1
  • x₁=1,x₂=0 → g(10)≈1
  • x₁=1,x₂=1 → g(−10+20+20)=g(30)≈1

ให้ 1 ทุกกรณีที่มีอย่างน้อยหนึ่ง input เป็น 1 ตรงกับ OR พอดี สังเกตว่าต่างจาก AND แค่ค่า θ₀ (bias) จาก −30 เป็น −10 — ยิ่ง bias น้อยลง (ใกล้ 0 มากขึ้น) threshold การ activate ก็ต่ำลง ทำให้ "ง่ายขึ้น" ที่จะ output 1.

NOT ใช้ input เดียว θ₀=10, θ₁=−20: x₁=0 → g(10)≈1 และ x₁=1 → g(10−20)=g(−10)≈0 — ตรงข้ามกับ input พอดี.

สังเกตแพทเทิร์นที่ทั้งสามตัวอย่างใช้ร่วมกัน: ทุก logic gate คือ neuron เดียวที่เลือกค่า θ ให้ "จุดตัด" (threshold) ตรงกับเงื่อนไขของ gate นั้น — นี่คือฐานที่ Lesson 3 จะต่อยอดเป็นการ "เรียน" ค่า θ พวกนี้จากข้อมูลด้วย gradient descent แทนการตั้งมือ.

กลไกที่ต้องอธิบายได้
ทำไมต้องมี
θ ต้องมีขนาด (magnitude) ใหญ่พอ ไม่ใช่แค่ทิศทาง/สัดส่วนถูก — sigmoid ต้องเข้าใกล้ 0 หรือ 1 "ชัดเจน" (saturate) เพื่อให้ทำหน้าที่เป็น logic gate ได้แม่นยำ ถ้า |z| เล็ก sigmoid จะแกว่งอยู่แถว 0.5 ไม่ใช่ 0/1 เด็ดขาด
เปลี่ยนแล้วเกิดอะไร
ลอง scale θ ของ AND ลง 20 เท่า (θ=[−1.5,1,1] แทน [−30,20,20] ทิศทาง/สัดส่วนเดิมทุกตัว) ที่ x₁=1,x₂=1: z=−1.5+1+1=0.5 → g(0.5)≈0.62 (ไม่ใช่ ≈1 อีกต่อไป ยังแกว่งใกล้ 0.5) ทั้งที่ทิศทาง θ ถูกทุกตัว — เพราะ |z| เล็กเกินไปจนไม่ตกเขต saturation
เชื่อมกับ
sigmoid ที่ไม่ saturate (|z| เล็ก) มีอนุพันธ์ใกล้ 0.25 (ค่าสูงสุด) ตรงข้ามกับปัญหา vanishing gradient ใน Lesson 3/5 ที่เกิดจาก saturate มากเกินไป — นี่คือ trade-off เดียวกัน: ยิ่ง confident (saturate) ยิ่งเรียนช้า (gradient เล็ก), ยิ่งไม่ saturate ยิ่งเรียนเร็วแต่ output ไม่เด็ดขาด
คำถาม 4Logic Gate Neuron
AND gate จาก neuron เดียวใช้ θ₀=−30, θ₁=20, θ₂=20 คำนวณ h(x)=g(θ₀+θ₁x₁+θ₂x₂) ที่ x₁=1, x₂=0 ได้ผลลัพธ์เท่าไหร่ (ประมาณ)?

5. Vectorization & Linear Algebra: เครื่องมือที่ใช้เขียนสูตรให้กระชับ

ก่อนเข้าสูตร Forward Computation จริง สไลด์ทวน Linear Algebra พื้นฐานที่ต้องคำนวณมือได้ทันที เพราะทุกสูตรของ Neural Network เขียนในรูป vector/matrix ทั้งหมด.

เวกเตอร์ u=(3,4) มีขนาด ||u|| = √(3²+4²) = √25 = 5 (ทฤษฎีพีทาโกรัส) และทิศทาง (unit vector) คือ w = (3/5, 4/5) (หารทุกสมาชิกด้วยขนาดของมันเอง เพื่อให้ขนาดใหม่เท่ากับ 1 พอดี).

สไลด์ทิ้งคำถามไว้ให้ลองคำนวณเอง: เวกเตอร์ [1,2,3] มีขนาดเท่าไหร่? ใช้สูตรเดียวกันแต่ขยายเป็น 3 มิติ: ||[1,2,3]|| = √(1²+2²+3²) = √(1+4+9) = √14 ≈ 3.742.

สูตรนี้คือรากฐานของ ||u||² = u·u (ขนาดยกกำลังสอง เท่ากับ dot product ของเวกเตอร์กับตัวเอง) ที่จะใช้อีกในการคำนวณ regularization term ของ Lesson 1 (Σθⱼ²) ซึ่งก็คือ ||θ||² นั่นเอง.

เมทริกซ์ A = [[3,4,38],[8,46,54]] มี 2 แถว 3 คอลัมน์ ดังนั้น m=2, n=3 (มิติ 2×3) องค์ประกอบ a₂₃ อ่านว่า "แถว 2 คอลัมน์ 3" คือเลข 54 ส่วนเลข 38 อยู่ที่แถว 1 คอลัมน์ 3 จึงเขียนเป็น a₁₃ (i=1, j=3).

กฎการอ่าน subscript ของ matrix (แถวก่อน คอลัมน์หลัง) นี้ใช้สัญกรณ์เดียวกับ θ_ij^[l] ที่เพิ่งเรียนไปในหัวข้อ 3 พอดี (i=ปลายทาง/แถว, j=ต้นทาง/คอลัมน์).

คำถาม 5Vector Length
เวกเตอร์ [1,2,3] มีขนาด (length/norm) เท่ากับเท่าไหร่ ตามสูตร Euclidean magnitude?

เมทริกซ์ A = [[1,2],[2,0],[4,4]] (3×2) คูณเวกเตอร์ [1,0]ᵗ: แต่ละแถวคูณแล้วบวกกัน:

  • แถว 1: 1×1+2×0=1
  • แถว 2: 2×1+0×0=2
  • แถว 3: 4×1+4×0=4

ได้ผลลัพธ์ [1,2,4]ᵗ (คือดึงคอลัมน์แรกของ A ออกมาตรงๆ) ลองคูณกับ [0,1]ᵗ แทน:

  • แถว 1: 1×0+2×1=2
  • แถว 2: 2×0+0×1=0
  • แถว 3: 4×0+4×1=4

ได้ [2,0,4]ᵗ (คือดึงคอลัมน์ที่สองของ A ออกมา) — พอเอาสองผลลัพธ์นี้มาเรียงเป็นคอลัมน์ของเมทริกซ์เดียวกัน (เทียบเท่าการคูณ A ด้วย Identity Matrix I₂ ทั้งก้อน) จะได้ A กลับมาเหมือนเดิมทุกตัว.

นี่คือเหตุผลที่ A×I = A เสมอ: การคูณด้วย identity matrix คือการคูณด้วย "เวกเตอร์หน่วย" ของแต่ละแกนพร้อมกันทุกแกน จึงได้เมทริกซ์เดิมกลับมาไม่เปลี่ยนแปลง.

กลไกที่ต้องอธิบายได้
ทำไมต้องมี
ทุกสูตรของ NN (z=θ·a, cost=Σ, regularization=Σθ²) เขียนเป็น operation บนเวกเตอร์/เมทริกซ์ได้ล้วนๆ เพราะ "ผลรวมถ่วงน้ำหนัก" คือนิยามของ dot product พอดี — ถ้าไม่มีภาษานี้ทุกสูตรต้องเขียนเป็นผลรวม Σ ทีละพจน์ ทั้งช้าและอ่านยาก
เปลี่ยนแล้วเกิดอะไร
ลองหาขนาดของเวกเตอร์ [3,4,12] แทน [1,2,3]: ||[3,4,12]|| = √(9+16+144) = √169 = 13 (ลงตัวพอดี ต่างจาก √14 ที่ไม่ลงตัว) — แสดงว่าสูตรพีทาโกรัสมิติเดียวกันใช้ได้กับเวกเตอร์กี่มิติก็ได้ ไม่จำกัดแค่ 2-3 มิติที่วาดภาพได้
เชื่อมกับ
||θ||² (ขนาดเวกเตอร์ยกกำลังสอง) คือนิยามเดียวกับ regularization term Σθⱼ² ใน Lesson 1 และ Lesson 3 พอดี — regularization ไม่ใช่สูตรใหม่ แค่ "บีบขนาดเวกเตอร์ θ ให้เล็กลง" ด้วยภาษาเดียวกับที่เพิ่งเรียน

จากเมทริกซ์ A = [[3,4,38],[8,46,54]] (2 แถว, 3 คอลัมน์) องค์ประกอบ a₂₃ มีค่าเท่ากับเท่าไหร่?
คำถาม 7Identity Matrix
ทำไมการคูณเมทริกซ์ A ด้วย Identity Matrix I (A×I) จึงได้ผลลัพธ์เท่ากับ A ทุกครั้งไม่เปลี่ยนแปลง?

6. Vectorized Linear Regression: จาก For Loop สู่ Matrix

จาก h(x)=1+2x₁+3x₂ (θ₀=1,θ₁=2,θ₂=3) กับ 3 examples ที่ x₁=0 ทุกแถว และ x₂=1,2,3: แทนค่าทีละแถว:

  • แถว 1 (x₁=0,x₂=1): h=1+2(0)+3(1)=1+0+3=4
  • แถว 2 (x₁=0,x₂=2): h=1+0+3(2)=1+6=7
  • แถว 3 (x₁=0,x₂=3): h=1+0+3(3)=1+9=10

เขียนเป็น matrix form ได้ h(X)=Xθ โดย X คือ matrix 3×3 (รวมคอลัมน์ x₀=1) และ θ คือ column vector [1,2,3]ᵗ ผลคูณ matrix-vector นี้ให้ผลลัพธ์ [4,7,10]ᵗ ในการคำนวณครั้งเดียว แทนการวน for loop ทีละแถว 3 รอบ.

นี่คือเหตุผลที่ NumPy เร็วกว่า Python list ธรรมดา (สไลด์หัวข้อ Vectorization หน้า 19 เปรียบเทียบเวลารันจริงระหว่าง for loop กับ numpy array).

กลไกที่ต้องอธิบายได้
ทำไมต้องมี
การคูณ matrix แทน for loop ไม่ได้ลดจำนวนการคูณ/บวกที่ต้องทำจริง (ยังคือ O(m×n) operations เท่าเดิม) แต่เปลี่ยนวิธี "สั่งงาน" ฮาร์ดแวร์ — CPU/GPU มีหน่วยคำนวณแบบขนาน (SIMD/BLAS) ที่ทำ dot product หลายตัวพร้อมกันได้ ถ้าเขียนเป็น Python for loop ทีละตัว ฮาร์ดแวร์ใช้ความสามารถนี้ไม่ได้เลย
เปลี่ยนแล้วเกิดอะไร
ถ้าข้อมูลจาก 3 examples เป็น 3,000 examples (1,000 เท่า) จำนวน FLOPs ที่ต้องคำนวณโต 1,000 เท่าเท่ากันทั้ง for loop และ vectorized (asymptotic complexity เท่าเดิม) แต่เวลารันจริงของ vectorized โตช้ากว่ามาก เพราะคูณเวกเตอร์ยาวได้ในคำสั่งเดียว ไม่ใช่ 3,000 คำสั่งแยก — นี่คือความต่างระหว่าง "ความซับซ้อนเชิงทฤษฎี" กับ "เวลารันจริงบนฮาร์ดแวร์"
เชื่อมกับ
หลักการเดียวกับที่ Lesson 4 หัวข้อ 3 ใช้เลือก mini-batch size — ยิ่ง batch ใหญ่ยิ่งใช้ประโยชน์จาก matrix multiplication เต็มที่ (เร็วต่อ 1 ตัวอย่าง) แต่ต้องแลกกับหน่วยความจำ

7. Shallow Neural Network สร้าง XNOR จาก AND, OR, NOT

ตัวอย่างสุดท้ายก่อนเข้า Forward Computation เต็มรูปแบบ: รวม gate เดี่ยวๆจากหัวข้อ 4 (AND, OR, NOT) มาต่อกันเป็น 2 layer เพื่อสร้าง XNOR (ตรงข้ามกับ XOR — ให้ 1 เมื่อ input เหมือนกัน).

ไล่ตาราง truth table ทีละแถว:

  • (x₁,x₂)=(0,0): x₁∧x₂=0, ¬x₁=1, ¬x₂=1, (¬x₁)∧(¬x₂)=1 → h(x)=1 (เพราะ "x₁∧x₂" OR "(¬x₁)∧(¬x₂)" = 0 OR 1 = 1)
  • (0,1): x₁∧x₂=0, ¬x₁=1,¬x₂=0, (¬x₁)∧(¬x₂)=0 → h(x)=0
  • (1,0): เหมือนกัน h(x)=0
  • (1,1): x₁∧x₂=1, (¬x₁)∧(¬x₂)=0 → h(x)=1

ผลลัพธ์ h(x)=[1,0,0,1] คือ "ให้ 1 เมื่อ x₁ กับ x₂ เท่ากัน" ซึ่งคือนิยามของ XNOR พอดี.

โครงสร้างที่ต่อกัน: hidden layer มี 2 node — node แรกคือ AND gate (θ₀=−30,θ₁=20,θ₂=20 จากหัวข้อ 4) คำนวณ x₁∧x₂ node ที่สองคือ "(¬x₁)∧(¬x₂)" (AND gate ที่รับ input เป็นผลลัพธ์จาก NOT gate ของ x₁,x₂ ก่อน) แล้ว output layer เป็น OR gate ที่รับผลจากทั้งสอง hidden node มารวมกัน.

นี่คือภาพที่ตอบคำถามหัวข้อ 2 อย่างเป็นรูปธรรม: การต่อ node เดี่ยวๆ (ที่ทำ logic gate ง่ายๆได้) เข้าด้วยกันเป็นหลาย layer ทำให้คำนวณ function ที่ node เดียวทำไม่ได้ (XOR/XNOR) ได้สำเร็จ.

กลไกที่ต้องอธิบายได้
ทำไมต้องมี
ตัวอย่างนี้พิสูจน์ compositionality: AND กับ "(¬x₁)∧(¬x₂)" เป็นฟังก์ชัน linearly separable ทั้งคู่ (TLU เดี่ยวทำได้) แต่พอเอามารวมกันด้วย OR ในอีก layer หนึ่ง ได้ฟังก์ชันที่ linearly separable ไม่ได้ (XNOR) — เพราะแต่ละ hidden node "ตัดพื้นที่คนละมุม" แล้ว output layer แค่รวมผลตัดสินใจที่ทำไปแล้ว ไม่ต้องตัดสินใจแบบ non-linear เองทั้งหมด
เปลี่ยนแล้วเกิดอะไร
ถ้าสลับ output gate จาก OR เป็น AND (เก็บ hidden 2 ตัวเดิม): hidden1(AND)=1 เฉพาะ (1,1), hidden2("(¬x₁)∧(¬x₂)")=1 เฉพาะ (0,0) — สองตัวนี้ไม่เคยเป็น 1 พร้อมกันเลย (mutually exclusive by design) ดังนั้น AND ของทั้งสองจะได้ 0 เสมอทุก input — network พังกลายเป็น output คงที่ 0 ทั้งที่โครงสร้าง 2 layer เหมือนเดิม ต่างแค่ gate สุดท้าย
เชื่อมกับ
หลักการ "แต่ละ hidden unit ตัดสินใจคนละเงื่อนไข แล้ว output รวมผล" คือกลไกเดียวกับที่ Lesson 3-4 ใช้อธิบายว่าทำไมเครือข่ายลึกสร้าง decision boundary ซับซ้อนได้จากหน่วยเชิงเส้นง่ายๆจำนวนมาก
คำถาม 8XNOR Construction
จาก truth table การสร้าง XNOR ด้วย AND/OR/NOT ที่ (x₁,x₂)=(0,1) ค่า h(x) สุดท้ายเท่ากับเท่าไหร่ และเพราะเหตุใด?

8. Forward Computation: คำนวณมือครั้งแรกแบบเต็มโครงข่าย

นี่คือสูตรที่ต้องคำนวณได้ทันทีตลอดวิชา: โครงข่ายมี input x₁,x₂ → hidden layer 3 node (a₁⁽¹⁾,a₂⁽¹⁾,a₃⁽¹⁾) → output 1 node.

ขั้นที่ 1 (คำนวณ layer 1): แต่ละ hidden node คำนวณ weighted sum ก่อน แล้วผ่าน g:

  • z₁⁽¹⁾ = θ₁₀⁽¹⁾ + θ₁₁⁽¹⁾x₁ + θ₁₂⁽¹⁾x₂, ตามด้วย a₁⁽¹⁾ = g(z₁⁽¹⁾)
  • z₂⁽¹⁾ = θ₂₀⁽¹⁾+θ₂₁⁽¹⁾x₁+θ₂₂⁽¹⁾x₂, a₂⁽¹⁾=g(z₂⁽¹⁾)
  • z₃⁽¹⁾=θ₃₀⁽¹⁾+θ₃₁⁽¹⁾x₁+θ₃₂⁽¹⁾x₂, a₃⁽¹⁾=g(z₃⁽¹⁾)

ขั้นที่ 2 (คำนวณ layer 2/output): รวม activation ทั้ง 3 ตัวจาก layer 1 (ไม่ใช่ x₁,x₂ ดิบๆอีกแล้ว): z₁⁽²⁾ = θ₁₀⁽²⁾+θ₁₁⁽²⁾a₁⁽¹⁾+θ₁₂⁽²⁾a₂⁽¹⁾+θ₁₃⁽²⁾a₃⁽¹⁾ แล้ว h_θ(x) = a₁⁽²⁾ = g(z₁⁽²⁾).

สังเกตรูปแบบที่ซ้ำกันทุก layer: "คูณ weight บวกกัน (z) แล้วผ่าน g (a)" ต่างกันแค่ layer ที่ลึกกว่าใช้ a ของ layer ก่อนหน้าเป็น input แทน x ดิบๆ — รูปแบบนี้จะขยายเป็นสูตรทั่วไปของ deep network ใน Lesson 4.

กลไกที่ต้องอธิบายได้
ทำไมต้องมี
สูตรต้องแบ่งเป็น "z แล้ว a" (ไม่คำนวณ a รวดเดียว) เพราะ backpropagation ใน Lesson 3 ต้องแยกอนุพันธ์เป็น 2 ขั้นตามลำดับนี้พอดี (∂a/∂z คือ g' และ ∂z/∂θ คือ a ของ layer ก่อนหน้า) — ถ้าไม่แยกจะไม่มี "จุดต่อ" ให้ chain rule ไล่ทีละขั้นได้
เปลี่ยนแล้วเกิดอะไร
ถ้า hidden layer มี 5 node แทน 3 node สูตร z₁⁽²⁾ เปลี่ยนจาก 4 พจน์ (bias+3 hidden) เป็น 6 พจน์ (bias+5 hidden): z₁⁽²⁾=θ₁₀⁽²⁾+Σₖθ₁ₖ⁽²⁾aₖ⁽¹⁾ (k=1..5) และ dimension ของ θ⁽²⁾ เปลี่ยนจาก 1×4 เป็น 1×6 ตามกฎ (จำนวน node ปลายทาง)×(จำนวน node ต้นทาง+1) จากหัวข้อ 3
เชื่อมกับ
โครงสร้าง "z แล้ว a" นี้คือ 2 ใน 4 เทอมของสูตร backprop ที่ Lesson 3 จะพิสูจน์ (g' มาจากขั้น a=g(z), a⁽ˡ⁻¹⁾ มาจากขั้น z=θ·a) และขยายเป็นสูตรทั่วไปของ L layer ใน Lesson 4
คำถาม 9Forward Computation
ในการคำนวณ z₁⁽²⁾ (ค่า z ของ output node ในโครงข่าย 2 layer ที่มี hidden layer 3 node) ตัวแปรที่ถูกนำมาคูณกับ θ นั้นคืออะไร?
คำถาม 10Vectorization
เหตุผลหลักที่การคำนวณ cost function แบบ vectorized (h=np.dot(X,theta)) เร็วกว่าการวน for loop ทีละ training example คืออะไร?

ชัยชนะของบทเรียนนี้
คุณควรอธิบายได้ว่าทำไมต้องมี Neural Network (ไม่ใช่แค่เพิ่ม polynomial feature), อ่านสัญกรณ์ θ_ij^[l], a_j^[l] ได้ถูกต้อง, คำนวณ logic gate จาก neuron เดียวได้ (AND/OR/NOT), อธิบายได้ว่าทำไม XOR ต้องใช้ 2 layer, และคำนวณ Forward Computation เต็มโครงข่ายมือได้ตั้งแต่ input จนถึง h_θ(x) — ทั้งหมดนี้คือสูตรเดียวกันที่ Lesson 3 จะสอน backpropagation ย้อนกลับ.
