1. Vanishing/Exploding Gradients: ผลสืบเนื่องจาก Chain Rule ที่ยาวเกินไป

ย้อนสูตรจาก Lesson 4 หัวข้อ 1: ∂J/∂θ₁,₁⁽ᴸ⁻¹⁾ = δ⁽ᴸ⁾·θ₁,₁⁽ᴸ⁾·g'(z₁⁽ᴸ⁻¹⁾)·a₁⁽ᴸ⁻²⁾ — ถ้าเครือข่ายมี 10 layer การหา gradient ของ layer แรกสุดต้องคูณเทอม g'(z) ต่อกันเกือบ 10 ตัว (1 ตัวต่อ layer ที่ผ่าน).

  • Exploding: ถ้าแต่ละเทอมมีค่า >1 (เช่น weight เริ่มต้นใหญ่) การคูณ 10 ตัวที่ >1 ซ้ำกันจะทำให้ gradient ใหญ่ขึ้นแบบทวีคูณ (exponential) จนอัปเดต weight กระโดดสุ่มไม่ลู่เข้า
  • Vanishing: ถ้าแต่ละเทอมมีค่า <1 (เช่น g'(z) ของ sigmoid สูงสุดแค่ 0.25 ตามที่พิสูจน์ใน Lesson 3 หัวข้อ 5) การคูณ 10 ตัวที่ <1 ซ้ำกันจะทำให้ gradient เล็กลงแบบทวีคูณจนเข้าใกล้ 0 — 0.25¹⁰ ≈ 0.00000095 (เล็กมากจนแทบไม่มีการอัปเดต weight ของ layer แรกๆเลย)

นี่คือเหตุผลที่ layer ที่อยู่ใกล้ input มักเรียนรู้ช้ากว่า layer ใกล้ output มากในเครือข่ายลึกที่ใช้ sigmoid.

ปัญหาไม่ได้อยู่แค่ "ค่าเฉลี่ยของ g'(z) น้อยกว่า 1" แต่ยังมีปัญหา saturation: ถ้า z มีค่ามากหรือน้อยเกินไป (ไม่ใกล้ 0) sigmoid จะแบนราบสนิท (g'(z)≈0 เป๊ะ ไม่ใช่แค่เล็ก).

ตรงนี้คือเหตุผลที่ ReLU (จาก Lesson 3 หัวข้อ 5) ถูกเลือกเป็นค่าเริ่มต้นสำหรับ hidden layer: อนุพันธ์ของมันเป็น 1 คงที่เมื่อ z≥0 (ไม่มี saturation ในโซนบวก) ทำให้ไม่ลดขนาด gradient ไม่ว่าจะผ่านกี่ layer.

แต่ ReLU ก็แลกมาด้วยปัญหาใหม่ (ตายที่ z<0 และเสี่ยง exploding เมื่อ activation บวกไม่มีขอบเขตบน) จึงต้องมี gradient clipping (ตัดค่า gradient ไม่ให้เกิน threshold ก่อน update) ช่วยแก้ฝั่ง exploding.

2. Weight Initialization: ทำไม "สุ่มเฉยๆ" ไม่พอ

สไลด์เว้นคำตอบไว้ให้คำนวณ: มี 100 input x₁,…,x₁₀₀=1 ทุกตัว weight θ ~ N(0,1) (สุ่มจาก normal distribution ค่าเฉลี่ย 0 variance 1) z₁⁽¹⁾ = θ₁₀⁽¹⁾+θ₁₁⁽¹⁾x₁+…+θ₁,₁₀₀⁽¹⁾x₁₀₀:

  • mean: ผลรวมของตัวแปรสุ่มที่มี mean=0 ทุกตัว บวกกันยังได้ mean=0 (ค่าคาดหวังของผลรวม = ผลรวมของค่าคาดหวัง)
  • variance: เพราะแต่ละเทอม θᵢxᵢ เป็นอิสระกัน variance ของผลรวม = ผลรวมของ variance แต่ละเทอม = Var(θᵢ)·xᵢ² = 1×1² = 1 ต่อเทอม รวม 100 เทอมได้ variance = 100

ตรงกับที่สไลด์เตือนไว้ "Variance ของ input โตขึ้นตามจำนวน input" พอ variance ของ z ใหญ่ขนาดนี้ (100 เทียบกับ 1 ตอนตั้งต้น) z มีโอกาสสูงที่จะหลุดไปอยู่ในโซน saturation ของ sigmoid (z ห่างจาก 0 มากๆ) ตั้งแต่ layer แรกเลย.

นี่คือเหตุผลที่ "สุ่ม weight เฉยๆ" ไม่พอ ต้องคุม variance ให้เหมาะกับจำนวน input ด้วย.

ทั้ง 3 วิธีแก้ปัญหาเดียวกัน (variance ของ z ไม่ควรโตหรือหดตามจำนวน input/output) ด้วยสูตรต่างกันเล็กน้อย:

  • LeCun (1998): var = 1/fan_in (fan_in = จำนวน node ที่ส่ง input เข้ามา) — เหมาะกับ SELU
  • Xavier/Glorot (2010): var = 2/(fan_in+fan_out) (คำนึงถึงทั้ง forward และ backward pass พร้อมกัน) — เหมาะกับ sigmoid/tanh/softmax
  • He/Kaiming (2015): var = 2/fan_in — เหมาะกับ ReLU และตัวแปรของมัน (ตัวเลข 2 ในตัวเศษชดเชยที่ ReLU "ตัดครึ่งค่าลบทิ้ง" ทำให้ variance ที่ออกมาจาก ReLU ลดลงครึ่งหนึ่งโดยธรรมชาติ ต้องเพิ่มตัวคูณ 2 มาชดเชย)

กฎจำง่ายจากสไลด์หัวข้อถัดไป: ReLU/Leaky ReLU ใช้ He, tanh/Sigmoid ใช้ Xavier.

3. Batch Normalization: Normalize z ก่อนเข้า Activation ทุก Layer

BN ทำ 2 ขั้นในทุก hidden layer ก่อน (หรือหลัง) activation function:

  • ขั้น 1 (normalize): z_norm⁽ⁱ⁾ = (z⁽ⁱ⁾−μ_B)/√(σ_B²+ε) — ลบด้วยค่าเฉลี่ยของ mini-batch (μ_B) แล้วหารด้วยส่วนเบี่ยงเบนมาตรฐานของ mini-batch (√(σ_B²+ε), ε ป้องกันหารด้วย 0) ผลคือ z_norm มี mean≈0, variance≈1 เสมอไม่ว่า layer ไหน
  • ขั้น 2 (scale/shift): z̃⁽ⁱ⁾ = γ·z_norm⁽ⁱ⁾+β — คูณด้วย γ และบวก β ที่เป็นพารามิเตอร์ที่เรียนรู้ได้เอง (ไม่ใช่ค่าคงที่) เพื่อให้เครือข่ายเลือกได้เองว่าจะ "คง" การ normalize ไว้เท่าไหร่ (ถ้า γ,β เรียนกลับมาเป็นค่าเดิมของ z ก็แปลว่า BN ไม่ช่วยตรงนี้ ปล่อยให้เป็นแบบเดิม)

เหตุผลที่ต้องมีขั้นที่ 2: ถ้า normalize แล้วหยุดเลย ทุก layer จะถูกบีบให้มี distribution เดียวกันตายตัว ซึ่งอาจไม่เหมาะกับทุกงาน จึงต้องให้เครือข่ายเรียนรู้ระดับการ "คลาย" เอง.

ตอน Training vs ตอน Test: ตอน train, μ_B และ σ_B² คำนวณจาก mini-batch ปัจจุบัน (เปลี่ยนไปทุก batch) แต่ตอน test ไม่มี "mini-batch" ให้คำนวณ (อาจมีแค่ 1 ตัวอย่าง) — ทางแก้คือเก็บ moving average ของ μ_B, σ_B² ที่สะสมมาตลอดการเทรน แล้วใช้ค่าเฉลี่ยสะสมนี้แทนตอน test (คงที่ ไม่เปลี่ยนตามข้อมูล test แต่ละตัว).

4. Layer Normalization: เมื่อไม่อยากพึ่ง Mini-batch

BN คำนวณ mean/variance "ไล่ตามคอลัมน์" คือรวบรวมค่าของ 1 neuron จากทุกตัวอย่างใน mini-batch (พึ่งพา batch size — ถ้า batch เล็กเกินไป สถิติที่คำนวณได้จะไม่น่าเชื่อถือ).

LayerNorm แก้ปัญหานี้ด้วยการคำนวณ mean/variance "ไล่ตามแถว" คือรวบรวมค่าของ neuron ทุกตัวภายใน 1 ตัวอย่างเดียว — ไม่ต้องพึ่งตัวอย่างอื่นใน batch เลย ทำให้:

  • ใช้ได้แม้ batch size=1
  • พฤติกรรมเหมือนกันทั้งตอน train และ test (ไม่ต้องเก็บ moving average แบบ BN)
  • เหมาะกับ Transformer ที่ batch statistics ผันแปรสูง

นี่คือเหตุผลที่ LayerNorm เป็นตัวเลือกมาตรฐานใน Transformer/LLM ในขณะที่ BN ยังนิยมใน CNN.

5. Keras ในภาคปฏิบัติ: MNIST ตัวอย่างเต็มรูปแบบ

ขั้นตอนมาตรฐาน 5 ขั้นของ Keras:

  1. โหลด/เตรียมข้อมูล
  2. สร้างโมเดล
  3. compile (เลือก loss, optimizer, metric)
  4. เทรนด้วย .fit()
  5. ประเมินผล

MNIST (เลขเขียนมือ 28×28 พิกเซล, 10 class) คือตัวอย่างที่สไลด์ใช้สาธิตทุกขั้น.

โมเดล 784→16→16→10 (MNIST แบบ flatten เป็นเวกเตอร์ 784 ก่อนเข้า Dense) นับพารามิเตอร์ทีละ layer ด้วยกฎเดียวจาก Lesson 2 หัวข้อ 5 (dimension ของ θ⁽ˡ⁾ = จำนวน node ปัจจุบัน × (จำนวน node ก่อนหน้า+1 สำหรับ bias)):

  • Layer 1: 16×(784+1) = 16×785 = 12,560
  • Layer 2: 16×(16+1) = 16×17 = 272
  • Layer 3 (output): 10×(16+1) = 10×17 = 170

รวม: 12,560+272+170 = 13,002 พารามิเตอร์ที่ต้องเรียนรู้ทั้งหมด — ตรงกับตัวเลขที่ Keras พิมพ์ออกมาจริงเป๊ะทุกหลัก.

เรียก model.fit(X, y, epochs=40, validation_split=0.2, batch_size=64) — เพราะ validation_split=0.2 ดึงข้อมูล 20% ไปเป็น validation ก่อน เหลือ training จริง 48,000 ตัวอย่าง (จาก 60,000 ตัวอย่างเต็มของ MNIST training set).

จำนวน mini-batch ต่อ epoch คำนวณตรงไปตรงมาตามสูตร Lesson 4 หัวข้อ 3: #mini-batches = #training examples ÷ batch size = 48,000 ÷ 64 = 750 batches.

เครือข่ายจะอัปเดต θ ทั้งหมด 750 ครั้งต่อ 1 epoch และเทรนซ้ำ 40 epoch (รวม 30,000 ครั้งของการอัปเดต θ ทั้งหมด).

6. Compile Options และ Softmax Layer

เมื่อ label เป็น integer เดี่ยว (เช่น MNIST แต่ละภาพมี label เป็นเลข 0-9 ตัวเดียว ไม่ใช่ one-hot vector) ใช้ loss="sparse_categorical_crossentropy" แทน categorical_crossentropy (ซึ่งต้องการ one-hot) — ประหยัดทั้งโค้ดแปลงข้อมูลและหน่วยความจำ.

ส่วน Softmax layer (ที่เรียนสูตรใน Lesson 3 หัวข้อ 6) ในบางกรณีเขียนแยกเป็น layer ต่างหากต่อจาก Dense layer สุดท้าย แทนที่จะฝัง activation='softmax' ไว้ใน Dense เลย — โครงสร้าง Input → Flatten → Dense → Softmax เป็นอีกวิธีเขียนโมเดลแบบ explicit ที่ให้ผลเหมือนกัน.

7. Overcome Overfitting ในโค้ดจริง

สไลด์ปิดท้ายด้วยการเขียน L2 regularization และ dropout ผ่าน Keras API จริง (เชื่อมกับ Lesson 4 หัวข้อ 6):

  • เพิ่ม kernel_regularizer=regularizers.l2(λ) เป็น argument ของ layer ที่ต้องการ regularize
  • เพิ่ม layers.Dropout(rate) เป็น layer แยกต่อท้าย layer ที่ต้องการทำ dropout

ทั้งสองคือการ "แปลสูตรทฤษฎีที่เรียนมาทั้งวิชา" เป็นโค้ด 1 บรรทัดเท่านั้น ไม่มีคณิตศาสตร์ใหม่.
