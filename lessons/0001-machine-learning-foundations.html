Machine Learning Foundations: การคำนวณที่ Deep Learning ทุกบทใช้ต่อ

Lecture นี้เป็นการปูพื้น ML ก่อนเข้า Deep Learning จริง — แนวคิด cost function, gradient descent, sigmoid, softmax, regularization ที่เรียนในบทนี้จะถูกใช้ซ้ำ "เหมือนเดิมทุกตัวอักษร" ในทุก Lecture ถัดไป (แค่เปลี่ยนจาก 1 node เป็นหลาย node/หลาย layer) เพราะฉะนั้นถ้าคำนวณมือได้ในบทนี้ Lecture 2-5 คือแค่ต่อยอดสัญกรณ์ ไม่ใช่ต่อยอดหลักการ.

อ่านเพิ่มก่อนเริ่ม (แนะนำ)
เนื้อหาบทนี้อิง Andrew Ng, Machine Learning (Coursera) เกือบทั้งหมด (สัญกรณ์ θ, gradient descent, ฯลฯ) — ถ้าเคยเรียนคอร์สนี้มาก่อนจะคุ้นสัญกรณ์ทันที.

1. ทำไม Deep Learning ถึง "ทรงพลัง"? สองเหตุผลจากสไลด์

ก่อนเข้าเนื้อหาคำนวณ สไลด์เกริ่นด้วยเหตุผล 2 อย่างว่าทำไม Deep Learning เอาชนะ Machine Learning แบบดั้งเดิมได้:

  • Scale for complex tasks — งานที่ต้องการ decision boundary แบบไม่เป็นเส้นตรง หรือมี input features จำนวนมาก (เช่นภาพ 28×28 พิกเซล = 784 features ต่อภาพ)
  • Automate feature engineering — เรียนรู้ features จากข้อมูลเองโดยไม่ต้องมีมนุษย์มานั่งออกแบบ feature ทีละตัว

เส้นเวลานี้สำคัญเพราะบอกว่า "backpropagation" (ที่จะเรียนละเอียดใน Lesson 3) ไม่ใช่ของใหม่ — Yann LeCun ใช้มันจับคู่กับ CNN สำเร็จตั้งแต่ปี 1989 เพื่ออ่านลายมือให้ธนาคาร.

แต่ Deep Learning ระเบิดความนิยมจริงในปี 2010 เป็นต้นมา เพราะสองเงื่อนไขที่ขาดไปก่อนหน้านั้นมาครบพร้อมกัน: ปริมาณข้อมูล (data) และพลังประมวลผล (GPU).

สังเกตกราฟด้านขวาที่จำนวนพารามิเตอร์ของโมเดล LLM/multimodal (แถบสีส้ม/ชมพู) พุ่งขึ้นแบบ exponential หลังปี 2017 (Transformer) เพราะทั้งสองเงื่อนไขนี้เติบโตต่อเนื่อง.

เครื่องมือนี้ควรลองเล่นจริงคู่กับ Lesson 2-3: มันให้ปรับจำนวน hidden layer/node แล้วเห็น decision boundary เปลี่ยนสดๆ — เป็นภาพเดียวกับที่จะพิสูจน์ด้วยมือทีหลังว่าทำไม node ยิ่งมาก decision boundary ยิ่งซับซ้อนขึ้นได้.

2. Linear Regression: จากจุดสองจุดสู่สมการเส้นตรง

สไลด์เริ่มด้วยตัวอย่างที่ทำมือได้จริง: มีจุดข้อมูล (0,0) และ (3,3) แล้วถามว่า hypothesis function h_θ(x) = θ₀ + θ₁x ของเส้นนี้คืออะไร.

คำนวณตรงไปตรงมา: θ₁ (slope) = Δy/Δx = (3−0)/(3−0) = 1 และเพราะเส้นผ่าน (0,0) จึง θ₀ (y-intercept) = 0 ดังนั้น h_θ(x) = 0 + 1·x = x.

สมการนี้ทำนายว่า y เท่ากับ x เป๊ะทุกจุด (สังเกตจาก scatter plot ตรงกลางสไลด์ที่จุดข้อมูลกระจายรอบเส้น y=x).

พอขยายจาก 1 ตัวแปรไปหลายตัวแปร (เช่น size x₁ และจำนวนห้องนอน x₂) สมการก็แค่บวก term เพิ่มเป็น h_θ(x) = θ₀+θ₁x₁+θ₂x₂+…+θₙxₙ — โครงสร้างเดียวกันทุกประการ แค่จำนวนตัวแปรมากขึ้น.

3. Cost Function & Gradient Descent: ทำไมสูตร θ := θ − α·∂J/∂θ ถึง "ลู่เข้า" หาค่าต่ำสุด

Cost function สำหรับ linear regression คือ Mean Squared Error: วัดว่าเส้นที่ทำนายห่างจากจุดข้อมูลจริงแค่ไหน (ยกกำลังสองเพื่อไม่ให้ค่าบวก/ลบหักลบกันเอง) เป้าหมายคือหา θ₀,θ₁ ที่ทำให้ J(θ₀,θ₁) น้อยที่สุด.

รูปชามนี้สำคัญ: linear regression's cost function เป็น convex (นูนแบบชามเดียว ไม่มีหลุมหลอก) เพราะฉะนั้นไม่ว่าจะเริ่ม θ ที่ไหน gradient descent ก็ไต่ลงไปเจอจุดต่ำสุดจุดเดียวได้เสมอ.

นี่คือสิ่งที่ ต่างจาก neural network ในบทถัดไปที่ cost function ไม่นูน (มีหลุมหลอกหลายจุด อย่างที่ Lesson 3 จะพูดถึง).

นี่คือกลไกที่คำนวณตามได้ทีละก้าว:

  • เริ่มที่ฝั่งซ้ายของชาม (θ₁', กราฟซ้าย) — เส้นสัมผัส (สีแดง) มีความชัน เป็นลบ เพราะกราฟกำลังลาดลง ดังนั้น ∂J/∂θ < 0 สูตรอัปเดต θ₁ := θ₁ − α·(ค่าลบ) จะเท่ากับ θ₁ + (ค่าบวก) คือ θ₁ เพิ่มขึ้น เคลื่อนไปทางขวาเข้าใกล้จุดต่ำสุด (θ₁'')
  • เริ่มที่ฝั่งขวาของชาม (กราฟขวา) — ความชันเส้นสัมผัสเป็น บวก สูตรจะกลายเป็น θ₁ − (ค่าบวก) คือ θ₁ ลดลง เคลื่อนไปทางซ้ายเข้าใกล้จุดต่ำสุดเหมือนกัน

เครื่องหมายลบหน้า α ทำหน้าที่ "กลับทิศให้เข้าหาจุดต่ำสุดเสมอ" ไม่ว่าจะเริ่มจากทางไหน นี่คือเหตุผลเชิงคณิตศาสตร์ที่สูตร gradient descent ใช้เครื่องหมายลบ ไม่ใช่บวก.

ขนาดของ α ควบคุมว่า "ก้าวแต่ละครั้งยาวแค่ไหน":

  • α เล็กเกินไป — ต้อง iterate เยอะมากกว่าจะถึงจุดต่ำสุด (ช้าแต่ปลอดภัย)
  • α ใหญ่เกินไป — อาจก้าวข้ามจุดต่ำสุดไปเลย แล้วแฉลบไปมา (oscillate) หรือแย่กว่านั้นคือ diverge (ค่า J สูงขึ้นเรื่อยๆ ไม่ลู่เข้า)

วิธีตรวจสอบจริงคือดูกราฟ J(θ) เทียบกับจำนวน iteration: ถ้า J ลดลงเรื่อยๆ แปลว่า α เหมาะสม ถ้า J แฉลบขึ้นๆลงๆหรือพุ่งขึ้น (Cost Overshoot) แปลว่า α ใหญ่เกินไป ต้องลดค่า α ลง.

คำถาม 2Gradient Descent
ที่จุดหนึ่งบนกราฟ J(θ₁) เส้นสัมผัส (slope ของ ∂J/∂θ₁) มีค่าเป็นบวก สูตร θ₁ := θ₁ − α·∂J/∂θ₁ จะทำให้ θ₁ เปลี่ยนแปลงอย่างไร?

4. Feature Scaling: ทำไมต้อง Normalize ก่อนเทรน

ปัญหาคือถ้า feature หนึ่งมีสเกลใหญ่มาก (เช่นขนาดบ้านเป็น ft² อยู่ในช่วง 1,000-5,000) แต่อีก feature เล็กมาก (จำนวนห้องนอนอยู่ในช่วง 1-5) contour ของ cost function จะยืดเป็นวงรีแคบยาว ทำให้ gradient descent ต้อง zig-zag เดินอ้อมนานกว่าจะถึงจุดต่ำสุด.

การ normalize ให้ทุก feature อยู่สเกลใกล้เคียงกันช่วยให้ contour กลมขึ้นและ gradient descent เดินตรงเข้าจุดต่ำสุดได้เร็วขึ้น.

ตัวอย่างนี้แสดงประเด็นสำคัญ:

  • size = 3000 อยู่ในช่วง [1000,5000] ให้ X_new = (3000−1000)/(5000−1000) = 2000/4000 = 0.5
  • #bedroom = 3 อยู่ในช่วง [1,5] ให้ X_new = (3−1)/(5−1) = 2/4 = 0.5

สังเกตว่าค่าตั้งต้นต่างกันมหาศาล (3000 vs 3) แต่ normalize แล้วได้ 0.5 เท่ากันทั้งคู่ เพราะทั้งสองค่าอยู่ "ตำแหน่งกึ่งกลางของช่วงตัวเองพอดี" (3000 อยู่กึ่งกลาง [1000,5000] และ 3 อยู่กึ่งกลาง [1,5]).

นี่คือสิ่งที่ min-max normalization ทำ: ไม่สนใจสเกลเดิม สนใจแค่ "ตำแหน่งสัมพัทธ์ภายในช่วงของตัวเอง" ทำให้ทุก feature อยู่ในช่วง [0,1] เท่ากันหมดก่อนเข้า gradient descent.

5. Logistic Regression & Decision Boundary: จาก θ ตัวเลขจริง สู่เส้นแบ่งที่มองเห็น

Logistic Regression ใช้ sigmoid function g(z) = 1/(1+e^(−z)) บีบผลลัพธ์ให้อยู่ในช่วง [0,1] แล้วตีความเป็นความน่าจะเป็น จุดตัดสินคือ predict y=1 เมื่อ θ₀+θ₁x₁+θ₂x₂ > 0 (เพราะ sigmoid(0)=0.5 พอดี คือจุดแบ่งครึ่ง) สไลด์ให้ค่า θ จริงมาคำนวณสองตัวอย่าง:

ตัวอย่างซ้าย (linear): θ₀=0, θ₁=−1, θ₂=1 ทดสอบจุด x₁=100 (size), x₂=90 (width): แทนค่า θ₀+θ₁x₁+θ₂x₂ = 0 + (−1)(100) + (1)(90) = −100+90 = −10.

เพราะ −10 ไม่มากกว่า 0 โมเดลจึงทำนาย y=0 คือ "Available" (ไม่ใช่ "Sold") — สังเกตว่าเส้นแบ่ง x₂ = x₁ พอดี (จาก −x₁+x₂=0) ตรงกับเส้นทึบในกราฟที่แบ่งจุดสีน้ำเงิน (Sold ซึ่งอยู่เหนือเส้น x₂>x₁) จากจุดสีแดง (Available ซึ่งอยู่ใต้เส้น x₂<x₁) พอดี.

ตัวอย่างขวา (non-linear): θ₀=−4, θ₁=1, θ₂=1 บน feature ที่ยกกำลังสอง (x₁², x₂²) ทดสอบจุด x₁=0, x₂=0: แทนค่า θ₀+θ₁x₁²+θ₂x₂² = −4+0+0 = −4 ไม่ ≥ 0 จึงทำนาย y=0 คือ "Available".

เส้นแบ่งคือ x₁²+x₂² = 4 ซึ่งคือวงกลมรัศมี 2 (เพราะ 4 = 2²) จุดใดๆที่อยู่ ใน วงกลมนี้ (รวมจุด (0,0) ที่ทดสอบ) จะได้ y=0 ("Available", จุดสีแดงในกราฟ) จุดที่อยู่ นอก วงกลมจะได้ y=1 ("Sold", จุดสีน้ำเงิน) — นี่คือตัวอย่างที่เห็นภาพชัดว่าแค่เปลี่ยน feature จาก x เป็น x² ก็ทำให้ decision boundary ที่เป็นเส้นตรงกลายเป็นวงกลมได้ โดยที่สมการยังเป็น "linear ใน θ" เหมือนเดิม.

6. Cost Function ของ Classification: ทำไมใช้ Log Loss แทน MSE

ถ้าใช้ MSE (จาก linear regression) ตรงกับ sigmoid function จะได้ cost function ที่ไม่นูน (non-convex, มีหลุมหลอกหลายจุด) ทำให้ gradient descent ติดหลุมได้ สไลด์เลยใช้ Cross-Entropy Loss แทน: Cost = −y·log(h(x)) − (1−y)·log(1−h(x)).

ฟังก์ชันนี้มีสมบัติ "ลงโทษหนักเมื่อทำนายผิดมั่นใจ":

  • ถ้า y=1 จริง แต่โมเดลทำนาย h(x)→0 (มั่นใจว่าไม่ใช่) → cost พุ่งไปที่ ∞
  • ถ้า y=1 และ h(x)→1 (ทำนายถูกและมั่นใจ) → cost เข้าใกล้ 0 พอดี

ฟังก์ชันนี้แหละที่ทำให้ cost function ของ logistic regression กลับมานูนเหมือน linear regression และ gradient descent ใช้สูตรอัปเดตหน้าตาเดียวกันได้ (θⱼ := θⱼ − α·(1/m)Σ(h(x⁽ⁱ⁾)−y⁽ⁱ⁾)x⁽ⁱ⁾) ทั้งที่ cost function ต้นทางหน้าตาต่างกันมาก — เป็นเพราะอนุพันธ์ของ cross-entropy กับ sigmoid ลดรูปมาเจอกันที่สูตรเดียวกันเป๊ะ.

7. Metrics: Confusion Matrix, ROC/AUC

ลองแทนตัวเลขสมมติให้จำสูตรได้แม่น: ถ้าทำนาย 100 กรณีได้ TP=40, TN=45, FP=5, FN=10:

  • accuracy = (40+45)/(40+45+5+10) = 85/100 = 0.85
  • precision = TP/(TP+FP) = 40/45 ≈ 0.89 (จากที่ทำนายว่าเป็นบวก 45 ครั้ง ถูกจริง 40)
  • recall = TP/(TP+FN) = 40/50 = 0.80 (จากของจริงที่เป็นบวก 50 ครั้ง จับได้ 40)

สังเกต trade-off: ถ้าอยากได้ recall สูงขึ้น (จับ positive ให้ครบ) มักต้องยอมให้ precision ต่ำลง (ทำนายมั่วเป็นบวกมากขึ้น) และในทางกลับกัน.

จุดสำคัญคือ ROC ไม่ใช่ metric ค่าเดียวแบบ accuracy — มันคือกราฟที่ไล่ threshold การตัดสินใจ (ปกติ 0.5) ไปเรื่อยๆแล้ววาด TPR = TP/(TP+FN) กับ FPR = FP/(FP+TN) ที่ทุก threshold.

เส้นทะแยง 45° คือ "โมเดลสุ่มเดา" ยิ่งเส้นโค้งของโมเดลโก่งขึ้นไปทางมุมซ้ายบนมากเท่าไหร่ (พื้นที่ใต้กราฟ หรือ AUC เข้าใกล้ 1) โมเดลยิ่งแยกสอง class ได้ดี.

8. Multiclass: One-vs-Rest และ Softmax

One-vs-Rest เทรน logistic regression k ตัว (k = จำนวน class) แต่ละตัวตอบคำถาม "เป็น class นี้ หรือไม่เป็น" แล้วเทียบ h⁽¹⁾(x), h⁽²⁾(x), h⁽³⁾(x) เลือก class ที่ค่าความน่าจะเป็นสูงสุด ข้อเสียคือต้องเทรนโมเดลแยกกัน k ตัว.

Softmax แก้ปัญหานี้ด้วยโมเดลเดียว: aᵢ = e^(zᵢ) / Σₙ e^(zₙ) ลองคำนวณตัวอย่างเล็กๆ: ถ้า 3 class มี logit ก่อน softmax เป็น z=[2, 1, 0]:

  • e²≈7.39, e¹≈2.72, e⁰=1 รวมกัน ≈ 11.11
  • probability = [7.39/11.11, 2.72/11.11, 1/11.11] ≈ [0.665, 0.245, 0.090] รวมกันได้ 1.0 พอดี

นี่คือเหตุผลที่ใช้ exponential แทนสัดส่วนตรงๆ: มันขยายค่าที่มากที่สุดให้เด่นชัดขึ้น (0.665 vs สัดส่วนดิบ 2/3≈0.5 ถ้าใช้สัดส่วนตรงๆ) และรับ logit ลบได้ด้วย (ต่าง sigmoid ตรงๆที่ map แค่ [0,1] ไม่รองรับผลรวม).

9. Model Evaluation: Train/Validation/Test และ k-fold Cross Validation

ไล่ตามขั้นตอนจริงในสไลด์:

  1. แบ่งข้อมูลทั้งหมด 80-20 เป็น train/test ก่อน
  2. เอา 80% train มาแบ่งเป็น 3 fold เท่าๆกัน
  3. รอบที่ 1: เก็บ Fold 1 ไว้ทดสอบ เทรนด้วย Fold 2+3 วัดผลบน Fold 1
  4. รอบที่ 2: เก็บ Fold 2 ไว้ทดสอบ เทรนด้วย Fold 1+3
  5. รอบที่ 3: เก็บ Fold 3 ไว้ทดสอบ เทรนด้วย Fold 1+2
  6. เฉลี่ยผลทั้ง 3 รอบเป็นคะแนนสุดท้ายของ hyperparameter ชุดนั้น แล้วเลือกชุด hyperparameter ที่ให้คะแนนเฉลี่ยดีที่สุด

จุดสำคัญคือข้อมูล test 20% ที่กันไว้ตอนแรกจะไม่ถูกแตะจนกว่าจะเลือก hyperparameter ได้แล้ว ป้องกันไม่ให้ตัวเลข test ถูก "มองเห็น" ระหว่างเลือกโมเดล.

10. Bias vs Variance: วินิจฉัยจากกราฟ Jtrain กับ Jcv

อ่านกราฟนี้เป็นกฎการวินิจฉัย 2 ข้อ:

  • High Bias (underfitting) เกิดที่ d น้อย (โมเดลง่ายเกินไป เช่น h(x)=θ₀+θ₁x เส้นตรงเส้นเดียว) — ทั้ง Jtrain (สีแดง) และ Jcv (สีเขียว) สูงทั้งคู่ เพราะโมเดลง่ายเกินกว่าจะ fit ได้ดีทั้งข้อมูล train และ validation
  • High Variance (overfitting) เกิดที่ d มาก (เช่น h(x)=θ₀+θ₁x+θ₂x²+θ₃x³+θ₄x⁴ เส้นหยักไปตามทุกจุด) — Jtrain ต่ำมาก (ท่องจำ training data ได้แม่นยำ) แต่ Jcv สูง (ทำนายข้อมูลใหม่แย่ เพราะไปท่องจำ noise ของ train มาด้วย)

จุดที่ดีที่สุดคือ d ตรงกลางกราฟที่ทั้งสองเส้นต่ำพร้อมกัน (ในภาพคือ d=2, เส้นพาราโบลาที่ fit จุดข้อมูลได้พอดีโดยไม่หยักตามทุกจุด).

คำถาม 6Bias vs Variance
ถ้าพบว่า Jtrain(θ) ต่ำมาก แต่ Jcv(θ) สูงมาก ควรวินิจฉัยปัญหาของโมเดลว่าอะไร และวิธีแก้ที่เหมาะสมที่สุดคือข้อใด?

11. Regularization: บีบ θ ให้เล็กโดยไม่ทิ้ง feature

แทนที่จะตัด feature ทิ้ง (ซึ่งเสียข้อมูลไปเลย) L2 regularization เพิ่ม penalty term λ·Σθⱼ² เข้าไปใน cost function บีบให้ทุก θ มีค่าน้อยลง (เข้าใกล้ 0 แต่ไม่ถึง 0 พอดี).

ยิ่ง λ มากเท่าไหร่ยิ่งบีบ θ ให้เล็กเท่านั้น ถ้า λ ใหญ่เกินไปจนทุก θ ≈ 0 โมเดลจะกลายเป็นเส้นแบนราบ (High Bias กลับมาแทน) นี่คือเหตุผลที่ λ เป็น hyperparameter ที่ต้องหาค่าที่สมดุลด้วย cross-validation เหมือนกับ degree of polynomial.

12. Unsupervised Learning: K-means Clustering

K-means ต่างจากทุกหัวข้อก่อนหน้าตรงที่ ไม่มี y label ให้เรียนรู้เลย — อัลกอริทึมวนสองขั้นตอนสลับกัน:

  • Assign step: สำหรับจุดข้อมูลทุกจุด x⁽ⁱ⁾ หา centroid μₖ ที่อยู่ใกล้ที่สุด แล้ว label จุดนั้นด้วย index ของ centroid นั้น
  • Update step: สำหรับ centroid ทุกตัว μₖ ย้ายตำแหน่งไปที่ค่าเฉลี่ยของจุดข้อมูลทั้งหมดที่ถูก assign เข้ามาในรอบนี้

ทำสองขั้นตอนนี้สลับกันไปเรื่อยๆจนกว่า assignment จะไม่เปลี่ยนแปลงอีก (converge) — สังเกตว่าไม่มีขั้นตอนไหนที่ใช้ gradient descent หรือ cost function แบบมี label เลย มันคือการจัดกลุ่มจากโครงสร้างของข้อมูลเองล้วนๆ.

คำถาม 7K-means
ในขั้นตอน "Update" ของ K-means algorithm หลังจาก assign จุดข้อมูลเข้ากลุ่มแล้ว ตำแหน่งใหม่ของ centroid μₖ แต่ละตัวคำนวณจากอะไร?
